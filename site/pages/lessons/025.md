# Infrared frame adventure

Use an identified infrared receiver, an owned ordinary NEC remote, and one
resistor-limited LED. The first valid frame earns one glow, the second earns
two flashes, and the third unlocks three quick flashes.

This is receive-only evidence:

`light → pulses → frame → validity → visible reward`

Nothing transmits, exports raw captures, replays an unknown protocol, or maps
a numeric field to an action. At 120 seconds the sketch turns both LEDs off,
releases every owned pin, and waits for Reset.

## Specimen gate

Connect a receiver only after its own marking and a primary datasheet establish
its supply range, physical pin order, idle polarity, carrier band, and output
level. Use only an ordinary remote you own whose harmless NEC buttons are known
in advance. Similar-looking three-pin modules do not inherit one another's
ratings or pin order.

If the exact specimens are uncertain, leave the receiver unpowered. The
automated software fixtures still exercise the decoder behind the scenes.

## Literal wiring

Unplug USB before changing the circuit.

| Signal | Mega | Exact connection |
|---|---:|---|
| TP-IR | D2 | identified receiver's marked OUT function |
| Receiver power | 5 V, GND | only when the exact datasheet permits 5 V |
| TP-LED | D45 | row 13a; 1 kΩ from 13c to 13f; LED anode 13h and cathode 15h; 15j to ground rail |
| Ground rail | GND | rail to one Mega GND pin |
| Ready | D13 | built-in LED |

The PDF plate shows the occupied Mega headers, breadboard letters, numbered
rows, center trench, resistor, LED legs, and ground return. Its receiver block
names electrical functions, not a universal physical pin order; map those
three functions from the exact specimen's marking and datasheet.

## Visible progression

| Scene | What appears on D45 | What it supports |
|---|---|---|
| ready | dark while D13 stays on | capture and both evidence endpoints initialized |
| first valid frame | one 650 ms glow | known evidence reached the decoder |
| second valid frame | two 250 ms flashes | a second valid frame advanced the count |
| third or later valid frame | three 150 ms flashes | the dependent celebration unlocked |
| NEC repeat | one 150 ms acknowledgement | a held known button did not advance the count |
| unknown protocol | two 150 ms flashes | uncertainty stayed visible; count unchanged |
| timing, integrity, overflow, or record fault | four 100 ms flashes | evidence failed closed |

Unknown evidence never advances the valid count. Do not seek unknown
transmitters to make the fault patterns; deterministic repository fixtures
cover those paths.

## Evidence model

`PulseCapture` owns D2 and its external-interrupt resource. Its interrupt path
records bounded edge timestamps only. A completed `PulseFrame` remains stable
until its matching sequence is acknowledged.

`InfraredDecoder` recognizes the classic 8-bit-address NEC form used by the
known fixture. It checks leader timing, 32 bits, a final mark, and both inverse
bytes. An unknown or invalid frame keeps its numeric fields at zero.

`InfraredRecordEncoder` can write an optional bounded line:

```text
IR1,<sequence>,<protocol>,<validity>,<address-hex>,<command-hex>
```

Serial prints that canonical record only as supporting context. D45 is the
primary observation path, and raw pulse evidence is never exported for replay.

## Narrative code

The example acquires resources, starts its fixed adventure clock, observes
capture, decides validity, and actuates the visible pattern. Its shutdown
deadline is input-independent:

```cpp
if (now.elapsedSince (adventureStarted).milliseconds () >= 120000)
{
    stopSafely ();
    return;
}

observeInfrared (adk::MicrosecondTimePoint (micros ()));
showFrameEvidence (now);
```

The automated suite remains behind the scenes. It covers ownership and
rollback, exact timing limits, repeats, corrupt inverse bytes, overflow, stale
acknowledgement, bounded records, timestamp wrap, deterministic replay,
shutdown, and claim reuse.

## Predict, observe, interpret

Before Reset, predict D13 will light while D45 remains dark after successful
acquisition. Observe D13 after setup and interpret it only as acquisition
evidence. Before each known press, predict the next D45 reward; observe TP-IR
and D45, then interpret agreement as evidence that the receive and decode path
reached the lamp, not as general receiver compatibility. Before two minutes,
predict both lamps will go dark; interpret that visible ending only as software
shutdown. Pin release and high impedance remain separate, unperformed physical
measurements.

## When the story stalls

| What you see | Inspect while unpowered |
|---|---|
| D13 never lights | board power, resource conflict, initialization path |
| D13 on; D45 dark | exact receiver identity and D2, LED polarity, rows 13/15, resistor, ground rail |
| every press looks unknown | known remote protocol, receiver idle polarity, pulse timing |
| one short flash while holding a button | normal NEC repeat; count unchanged |
| four quick flashes | timing/integrity evidence or bounded-record failure |
| no three-flash celebration | use only known buttons and allow each visible pattern to finish |
| lamps remain on after two minutes | unplug; fixed shutdown did not complete |
