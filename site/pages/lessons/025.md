# Infrared frame evidence

Status: **host verified; hardware acceptance open**
Energy class: **E1** — USB-powered Mega and resistor-limited evidence LEDs
Protocol boundary: **known NEC fixtures, receive only**

This lesson keeps four ideas separate:

`capture → frame → validity → record`

`InfraredDecoder` interprets immutable pulse evidence. It recognizes one
published NEC form, validates timing and inverse bytes, and reports uncertainty
without guessing. `InfraredRecordEncoder` then writes a bounded canonical
record:

```text
IR1,<sequence>,<protocol>,<validity>,<address-hex>,<command-hex>
```

The canonical Mega exercise uses an identified active-low demodulating receiver
and an owned ordinary kit remote whose harmless NEC buttons are known in
advance. Deterministic host tests supply the valid, unknown-leader, invalid
timing, repeat, overflow, and record fixtures. Nothing emits infrared, exports
raw captures, maps a command to an action, or replays captured pulses. Serial
prints the bounded record as optional supporting evidence; D45 is the primary
result signal.

## Circuit and evidence

| Signal | Mega pin | Connection |
|---|---:|---|
| Acquisition | D13 | built-in LED |
| Frame evidence / TP-LED | D45 | D45 → 1 kΩ → LED anode; cathode → GND |
| Receiver evidence / TP-IR | D2 | identified active-low receiver OUT |
| Receiver supply | 5 V, GND | only when the exact primary datasheet permits it |
| Probe reference | GND | logic-probe or meter reference |

Remove USB power before changing wires or attaching probe clips. The D13
acquisition LED remains on only after both evidence outputs initialize.
D45 repeats a four-second evidence window:

| Result | D45 cadence |
|---|---|
| valid NEC fixture | one 1 s pulse |
| unknown protocol | two 150 ms pulses |
| timing, integrity, overflow, or record fault | four 100 ms pulses |

The cadence makes every state distinguishable without color. Measure TP-LED
against GND; an LED being dark does not prove pin release or high impedance.

The pencil plate is an orientation aid, not an electrical schematic. Confirm
the receiver's actual pin order from its exact primary datasheet; the table
does not identify an unmarked module.

## Public evidence model

`PulseFrame` borrows immutable pulse storage and carries its sequence and
capture state. `InfraredDecoder::decode()` leaves the destination unchanged
only for an invalid API argument. Evidence classifications such as
`UnknownProtocol`, `TimingInvalid`, `IntegrityInvalid`, `Truncated`, and
`Overflow` are successful interpretations of a supplied frame; callers inspect
`InfraredFrame::validity`.

A `Valid` frame exposes numeric address and command fields. Those numbers are
evidence, not semantic actions. Invalid and unknown frames keep both fields
zero so policy code cannot accidentally use invented values.

`InfraredRecordEncoder::encode()` returns `Result<uint16_t>`. Check `.ok()`
before reading `.value()`. On insufficient caller storage, it reports
`CapacityExceeded`, writes no partial record, and returns zero bytes.

## Owned capture boundary

`PulseCapture` owns D2 and its external-interrupt resource. Its Mega adapter
maps receiver `LOW` to `Mark` and `HIGH` to `Space`. The interrupt path records
only bounded edge timestamps. `update()` publishes a stable frame after the
12 ms gap; decoding and record formatting happen in the ordinary run loop.
The frame remains stable until `acknowledge(sequence)` succeeds. New evidence
before acknowledgement reports overrun without mutating the published frame.

The first configuration accepts 100–10,000 µs pulse durations and requires a
12,000 µs frame gap. These are software gates for the lesson, not a receiver
performance claim.

## Narrative run loop

```cpp
observeInfrared       (now);
decideFrameEvidence   (frame);
recordFrameEvidence   (frame);
showFrameEvidence     (now);
```

The sketch creates the runtime, Mega capture adapter, owned capture endpoint,
owned LEDs, pure decoder, and pure encoder in dependency order. Setup acquires
D2, its interrupt, and both outputs. The loop updates capture from an explicit
microsecond timestamp, interprets a published frame, records the same frame,
acknowledges its sequence, and actuates the visible cadence. It uses no heap,
third-party receiver library, transmitter, or hidden component clock.

## Predict, observe, interpret

1. Predict D13 will illuminate only after D2, its interrupt, and both evidence
   outputs are acquired.
2. For a known valid button, predict TP-IR will show an active-low pulse train
   followed by one long D45 pulse.
3. Observe TP-IR and TP-LED together with a logic analyzer.
4. Interpret agreement as evidence that decode classification reached the
   circuit. It does not establish optical range or general remote compatibility.
5. Invoke the shutdown path and measure D45 separately from looking at the LED.
   High-impedance evidence remains a physical bench item.

## Specimen and receive-only boundary

Do not connect or power an unidentified module. Record its exact marking, primary
datasheet, supply range, idle polarity, carrier band, and pinout before wiring.
Use only an owned ordinary kit remote and known harmless NEC buttons. Raw
unknown captures are not exported or replayed. No transmitter is part of this
lesson.
