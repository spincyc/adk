# Lesson 035 — passage qualification

Status: **host verified; physical sensor acceptance open**

Energy class: **E0 software fixture**
Safety boundary: **classification and resistor-limited evidence LEDs only**

`PassageQualifier` turns two healthy, timestamp-aligned magnetic observations
into one bounded passage record:

`two observations → qualified boundary order → one passage record`

It is pure software. It owns no pin, endpoint, clock, storage, callback, sensor,
motor, gate, or lock. The canonical Mega sketch uses deterministic software
frames for `TP-A` and `TP-B`; they are not electrical sensor inputs.

Do not connect a `Linear Hall` or `Magnetic Spring` specimen until Lesson 034's
exact pinout, supply, topology, logic, stimulus, schematic, and current gates
are complete.

## Configuration and input

`PassageQualifierConfig` provides:

| Field | Contract |
|---|---|
| `boundaryDwell` | continuous activity needed to qualify one boundary |
| `passageTimeout` | maximum interval after first-boundary qualification |
| `duplicateWindow` | suppression interval after a terminal event |

All durations are nonzero and below the unsigned half-range.
`passageTimeout` is at least `boundaryDwell`.

Each `PassageInput` carries one `observedAt` timestamp, boundary A and B
`MagneticObservation` snapshots, and optional copied position evidence. The
input timestamp must equal both observation timestamps. `TP-A` and `TP-B` are
names for those internal fixture-trace columns, not board pins or electrical
test points.

## Phases and terminal records

| Phase | Meaning |
|---|---|
| `Idle` | no candidate |
| `FirstBoundary` | one boundary is active but has not finished dwell |
| `AwaitingSecond` | first boundary qualified; passage timeout is running |
| `Suppressing` | terminal event emitted; duplicates cannot be accepted |
| `Fault` | time or source evidence is invalid |

A sole boundary must remain active for the complete dwell. When the opposite
boundary finishes its own dwell at or before timeout, the qualifier emits one
`Accepted` record with direction `AToB` or `BToA`, increments the accepted
count once, and enters suppression.

`hasRecord` is true for exactly the terminal snapshot. The next later update
clears it. Snapshot observation itself does not consume the record.

## Suppression, retreat, and ambiguity

Rearm requires both boundaries inactive and duplicate-window expiry. A new
activation during suppression emits one `DuplicateSuppressed` record and
increments only the suppressed count. Holding the activation cannot count it
again and does not restart the window.

If the first boundary retreats before the opposite boundary qualifies, the
candidate cannot reverse into an accepted passage. The qualifier waits until
both are inactive, then returns to Idle without a record.

Simultaneous qualification is `Ambiguous`. A late opposite boundary is
`TimedOut`.

## Faults and recovery

Only `Valid`, Ok observations participate. Precedence is:

1. invalid time;
2. source fault;
3. ambiguity;
4. timeout;
5. completion.

An evidence failure during an active candidate emits one `EvidenceFault`
record, then enters Fault. An idle failure enters Fault without manufacturing a
record. Recovery requires a later healthy both-inactive frame and emits no
record.

Natural 32-bit rollover is valid. An exact half-range or larger apparent jump
faults. An identical same-time input is idempotent; changed same-time evidence
faults without partial mutation.

## Optional position evidence

Position corroborates direction but never decides whether the passage was
accepted. A nonzero, unclamped delta is reliable when its sign agrees with the
convention A-to-B positive and B-to-A negative.

Missing, zero, opposite, source-failed, or saturated position is retained as
explicit unreliable evidence. It does not reject an otherwise accepted
passage.

## Visible software-first progression

The canonical sketch drives three independent LEDs, each through 1 kΩ:

| Evidence | Meaning |
|---|---|
| `D30` | latest snapshot contains an Accepted record |
| `D31` | that accepted record is A-to-B |
| `D32` | qualifier is not in Fault |

The fixture first produces A-to-B, then B-to-A. It advances qualifier time in
10 ms steps but presents each frame for 250 ms, so the record LEDs remain
human-readable without changing the qualifier's timing evidence. Predict
D30/D31 before each record: accepted A-to-B lights both; accepted B-to-A lights
D30 without D31. D32 proves readiness separately. Serial is unnecessary.

The run stops independently after 120 seconds. LED darkness does not prove
released pins; measure release separately. Each direct LED is bounded to at
most 5 mA at 5 V, excluding the Mega baseline.

## Predict, observe, interpret

1. Predict D32 after initialization; interpret it only as readiness.
2. Predict the A dwell, B dwell, direction, and one-record snapshot.
3. Inspect the `TP-A`/`TP-B` trace columns in the canonical fixture, then
   compare their predicted order with board-visible D30/D31.
4. Reverse the sequence and predict D30 on with D31 off.
5. Inject a host-only duplicate, timeout, ambiguity, and timestamp mismatch.
6. Recover Fault only with a later healthy both-inactive frame.
7. Invoke shutdown; verify LED inactivity and pin release separately.

Remove USB for heat, odor, reset, unstable rail, unexpected LED state, or a
current-limit trip. Change wiring only while unpowered. Do not connect unknown
specimens, motion, a gate, lock, vehicle, launcher, ignition path, or safety
system.

## Software evidence and sources

Focused host tests cover directions, exact dwell and timeout edges, suppression,
chatter, retreat, ambiguity, source/time faults, recovery, rollover,
same-time frames, deterministic replay, position reliability, saturation,
reset, and saturating sequences and counters. These are software claims, not
physical sensor evidence.
