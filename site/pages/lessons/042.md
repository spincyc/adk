# Lesson 042 — tabletop course marshal

Status: **E0 host verified; powered fixture and bench acceptance open**

Energy class: **E0 copied-evidence project**
Safety boundary: **hand-moved card or unpowered model; no actuator**

The course marshal turns already-qualified evidence into one ordered,
replayable run:

`PIR eligibility + button press → checkpoints in order → finish agreement → frozen record`

PIR motion is never start authority. A debounced press from the configured
button is the sole authorizing action, and it succeeds only when the same
course-clock frame contains fresh, valid, non-stale PIR evidence in
`PirPhase::Motion`. A press outside that eligibility frame is not remembered.

## Bounded policy, not a sensor driver

`CourseMarshal` owns no pin, clock, display, bus, sensor, actuator, heap, or
persistent storage. Its configuration binds one through four semantic
checkpoint IDs to qualified optical source identities. Pins and input-array
order cannot redefine the course.

One update receives:

- the course timestamp;
- one optional start event from `CourseStartPolicy`;
- one immutable `PresenceSnapshot`; and
- up to four already-qualified checkpoint events.

The complete frame is validated before mutation. Equal-time events are ordered
by semantic slot. Distinct checkpoints inside the simultaneity window reject
as ambiguous instead of acquiring an accidental pin or array order. A finish
is accepted only after every checkpoint and same-frame agreement between the
reflective finish guard and valid approach-range evidence.

## Compact fixed storage

The first monolithic design buckled under the Mega 2560 SRAM gate:
`CourseMarshal` measured 653 bytes and its presenter 432 bytes. The remediated
API keeps every public object at or below 128 bytes by requiring six
caller-owned, fixed-capacity storage objects.

| Budget item | AVR bytes |
|---|---:|
| six caller-owned storages | 456 |
| storages plus marshal | 525 |
| storages plus marshal, start policy, and presenter | 639 |

These figures cover only the E0 course policies. They do not include source
policies, endpoints, diagnostics, display, linked sketch globals, or stack.
The canonical replay sketch measures 15,596 bytes of flash and 901 bytes of
static SRAM on the Mega 2560. Powered composition still requires aggregate
current, pin, cadence, and stack evidence. There is no heap and no storage
device; every run record is volatile.

The marshal retains references to all six storage objects for its lifetime.
Input-view pointers need remain valid only during `update()`. A terminal
record remains stable until explicit acknowledgment or reconstruction.
Reaching the final sequence number permanently rejects another start for that
object lifetime.

## Visible evidence without Serial

The presentation policy derives one bounded display cell and indicator intent
from a compact marshal snapshot:

| Visible path | Interpretation |
|---|---|
| three local checkpoint LEDs | accepted-prefix evidence in the canonical replay; the policy supports up to four |
| ready/heartbeat indicator | ready state and supplied-time progress |
| all-red indicator | rejected or faulted run |
| four-digit display | elapsed time or fault code |

The default experiment is deterministic replay. Predict each visible change,
observe it at the named output, then compare it with the frozen host record.
Serial is optional and never the only proof.

## Predict, observe, interpret

1. Supply valid PIR Motion evidence without a button press. Predict `Ready`,
   not `Running`.
2. Press the configured button in that same eligible frame. Predict one start
   event and no remembered authorization on a later frame.
3. Cross checkpoint IDs in configured order. Predict one more local LED after
   each accepted event.
4. Present two distinct checkpoints inside the simultaneity window. Predict
   rejection and all-red, independent of array order.
5. Reach the finish guard before all checkpoints, or without fresh approach
   range. Predict rejection with retained trigger evidence.
6. Complete all checkpoints and agreeing finish evidence. Predict a frozen
   accepted record whose elapsed time remains visible until acknowledgment.
7. Inject malformed time or failed required evidence. Predict a fault without
   a partially accepted checkpoint.

## Physical boundary

There is no canonical wiring table or electrical schematic for Lesson 042.
Exact optical, PIR, ultrasonic, button, display, and indicator specimens must
first close their identity, voltage, polarity, pull-up, emitter, current,
pin-claim, timing, and aggregate SRAM/stack gates. The project never drives a
gate, vehicle, launcher, motor, or other stored-energy mechanism.

Compilation, replay, documentation, and object-size measurements do not prove
physical operation. Incoming conformance and the complete E1 bench acceptance
record remain open.
