# Bounded motor intent

Status: **host verified; hardware acceptance open**
Primary experiment: **E1** — three resistor-limited LEDs, with no motor power
Optional continuation: **E2 draft** — only after a named driver and supply pass review

This lesson separates a motion request from electrical actuation:

`operator request → MotorIntent → requested/applied snapshot → LED adapter`

The controller accepts `Stopped`, `Forward`, and `Reverse` intent. A reversal
first applies zero duty and both direction signals inactive. It waits for the
configured dead time before applying the opposite direction. Stop dominates
every phase. A moving command is admitted only while its explicit
`PowerDomain` gate is active; the lesson admits that gate only after every LED
evidence endpoint initializes.

The primary experiment uses LEDs in place of an H-bridge. It makes the
direction truth table, PWM enable, and dark reversal interval directly
observable without energizing a motor. Serial is optional supporting evidence.

## Safe simulation

| Evidence signal | Mega pin | Connection |
|---|---:|---|
| Forward / TP-F | D22 | D22 → 1 kΩ → LED anode; cathode → GND |
| Reverse / TP-R | D23 | D23 → 1 kΩ → LED anode; cathode → GND |
| Enable / TP-E | D6 | D6 → 1 kΩ → LED anode; cathode → GND |
| Acquisition | D13 | built-in LED |

Remove USB power before wiring or moving a probe. The three external LEDs are
indicators only. Do not connect a motor, relay coil, or H-bridge power terminal
to a Mega pin.

The 1 kΩ resistors intentionally make this a low-current logic simulation. An
LED can reveal a direction state or changing PWM duty; it cannot prove that a
future motor receives adequate voltage, current, torque, or correct polarity.

## Controller contract

- `Stopped` requires duty zero.
- A moving command requires nonzero duty no greater than `maximumDuty`.
- Same-direction duty changes apply without reversal dead time.
- A direction reversal immediately applies `Stopped`.
- The opposite direction becomes applicable only at the explicit deadline.
- A stop during dead time cancels the pending motion.
- Invalid commands do not modify the last accepted state.
- Reset and shutdown return to stopped intent.

Time enters through the caller-provided `TimePoint`. The snapshot reports both
`requested` and `applied` commands, its phase, status, deadline, and transition
count. Tests replay the same requests and times without a hidden clock.

## Narrative run loop

The canonical sketch is structured around the domain:

```cpp
void loop ()
{
    const adk::TimePoint now (millis ());

    observeOperatorRequest (now);
    decideMotorIntent      (now);
    actuateMotorEvidence   ();
}
```

The adapter writes only the **applied** snapshot to the three evidence LEDs.
During reversal dead time, TP-F and TP-R are low and TP-E has zero duty. This
visible dark interval is deliberate behavior, not a pause or a failed loop.

## Predict, observe, interpret

1. **Acquire:** predict D13 illuminated only after every evidence endpoint is
   owned. Observe it after reset. It supports acquisition, not output safety.
2. **Forward:** predict TP-F high, TP-R low, and PWM at TP-E. Observe all three.
   This supports the applied forward truth table.
3. **Reverse:** request reverse while forward is applied. Predict a dark
   interval at all three LEDs before TP-R and TP-E become active.
4. **Stop:** request stop at every phase. Predict TP-F and TP-R low and TP-E at
   zero duty immediately.
5. **Shutdown:** invoke the shutdown path and measure the named test points.
   A dark LED alone does not prove a pin is high impedance.

Use a logic analyzer or oscilloscope for dead-time and PWM measurements. A
multimeter may show an average enable voltage but cannot establish pulse timing.

## Motor-power boundary

The published experiment does not power a motor. A future E2 continuation must
name one H-bridge variant and cite its primary datasheet. Before it can become
supported, record:

- motor stall current at the chosen current-limited supply;
- driver continuous/peak ratings, logic thresholds, flyback strategy, and
  thermal limit;
- separate logic and motor-power paths;
- a physical switch that removes motor power;
- restrained or raised motion with no pinch or entanglement exposure;
- measured inactive, forward, reverse, dead-time, fault, and reset behavior.

Software shutdown is not an emergency stop. Removing motor power is the stop
method. USB stays disconnected whenever the selected module could back-power
the Mega.

make upload-Lesson020MotorIntent PORT=/dev/ttyACM0

completed bench card is published, this lesson remains experimental.
