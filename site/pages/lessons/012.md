# Tabletop traffic junction

Status: **engine host verified; hardware adapter experimental**<br>
Energy class: **E1** — tabletop, USB-powered, resistor-limited indicators only

The fourth checkpoint composes the owned button, shift-register display, timed
traffic engine, vehicle signals, pedestrian signals, and visible countdown into
one tabletop junction.

The run loop remains a readable evidence chain:

`request → complete observation → legal phase → signals + countdown`

Predict the next phase and countdown before pressing the request button.
Observe the complete vehicle and pedestrian pattern through the LEDs, the
latched countdown glyph, and the all-red safe state during startup and injected
failure. Interpret a request as pending work rather than an immediate walk
command: the engine finishes the active safety interval before entering the
legal pedestrian sequence.

The project uses D22/D23/D24 for the 74HC595 display interface, D25 for the
pull-up pedestrian button, D30–D35 for the two red/yellow/green vehicle heads,
and D36/D37 for pedestrian walk/stop. D13 separately proves full resource
acquisition. Every external LED and display segment uses its own 330 Ω
resistor. Safe failure is all-red with the display blank; D30, D32, D33, and
D35 are named electrical test points for the two red/green interlocks. The
project is a logic trainer, not a controller for a road, vehicle, gate, or
safety system.

Host traces assert that conflicting greens are impossible and that every
reported circuit-health failure forces all red. The canonical Mega project
compiles (6,874 bytes flash, 419 bytes static RAM), but no physical junction
timing, output level, current, reset, or shutdown acceptance is claimed until
its bench card is recorded.
