# Tabletop traffic junction

Prerequisites: **Lessons 001–011**

Status: **engine host verified; hardware adapter experimental**<br>
Energy class: **E1** — tabletop, USB-powered, resistor-limited indicators only

This project composes the owned button, shift-register display, timed
traffic engine, vehicle signals, pedestrian signals, and visible countdown into
one tabletop junction.

The run loop remains a readable evidence chain:

`request → complete observation → legal phase → signals + countdown`

Build it in three quick wins: first make the two vehicle heads cycle, then add
the pedestrian request, then add the countdown. Each addition makes the model
more interesting and relies on the previous wiring still being correct. A
quarter-second D13 pulse says the complete project acquired its pins. The
model then runs for two minutes and releases every owned pin; press reset to
replay it.

Predict the next phase and countdown before pressing the request button. A
request becomes pending work rather than an immediate walk command: the engine
finishes the active interval before entering the pedestrian sequence.

The project uses D22/D23/D24 for the 74HC595 display interface, D25 for the
pull-up pedestrian button, D30–D35 for the two red/yellow/green vehicle heads,
and D36/D37 for pedestrian walk/stop. D13 separately pulses after full resource
acquisition. Every external signal LED uses its own 330 Ω resistor; every
display segment uses its own 1 kΩ resistor. A running fault requests all-red;
shutdown releases all output pins. D30, D32, D33, and D35 are named electrical
test points for the two red/green interlocks. The
project is a logic trainer, not a controller for a road, vehicle, gate, or
safety system.

Behind the scenes, host traces assert that conflicting greens are impossible
and that every reported circuit-health failure requests all red. The canonical
Mega project compiles, but no physical junction timing, output level, current,
reset, or shutdown result is claimed.
