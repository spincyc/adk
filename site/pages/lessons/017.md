# Bounded servo intent

Status: **host verified; hardware acceptance open**
Energy class: **E2** — separately powered, restrained micro servo

This lesson keeps four claims separate:

`button → BoundedServo intent → ServoOutput pulse → observed paper pointer`

- D13 says logic resources initialized.
- D30–D32 show the commanded low, middle, or high range.
- TP-S at D44 shows the commanded pulse.
- TP-V and the supply current point show external power.
- The paper pointer shows physical position.

A marker LED is evidence of software intent, not shaft position. A pulse is
evidence of an electrical command, not motion. A pointer observation is not
closed-loop feedback.

## Safety boundary

Use one exactly identified micro servo and its primary voltage, pulse, pin, and
current documentation. An unidentified “SG90-compatible” part is not admitted.
The first fixture carries only a soft paper pointer over a flat card—no latch,
linkage, hard stop, or useful load.

Servo positive comes from a separately regulated, current-limited supply
through a reachable physical switch or removable connector. It never connects
to Mega 5 V, VIN, USB 5 V, or an I/O pin. Join servo-supply negative and Mega
GND at one named common point. The common ground joins references, not positive
rails.

Open servo-positive power before every reset, upload, wiring change, or probe
change. Software shutdown, pulse detachment, and RAII destruction do not remove
external power and are not emergency stops.

Immediately open physical servo power for unexpected motion, chatter, stall,
heat, odor, current-limit operation, supply sag, reset, lost ground, malformed
TP-S waveform, or disagreement between command marker and pointer.

## Authoritative wiring

| Signal | Connection | Purpose |
|---|---|---|
| `CommandButton` | D22 to GND; internal pull-up | request the next bounded position |
| `LowMarker` | D30 → 220 Ω → LED → GND | low command intent |
| `MiddleMarker` | D31 → 220 Ω → LED → GND | middle command intent |
| `HighMarker` | D32 → 220 Ω → LED → GND | high command intent |
| `LogicReady` | D13 built-in LED | acquisition evidence |
| TP-S | D44/OC5C to servo signal | Timer5 pulse evidence |
| Common reference | Mega GND to servo-supply negative | signal reference |
| TP-V | across servo positive and supply negative | load-domain voltage evidence |
| Servo positive | admitted external supply through physical disconnect | load power |

D44 and Timer5 are exclusively owned. This conflicts with PWM on D44, D45, and
D46. Resource conflict fails before a pulse is emitted.

## Public model

`ServoCalibration` maps an explicit integer position domain to an admitted
microsecond pulse range:

```cpp
const adk::BoundedServoConfig config =
{
    {0, 1000, 1000, 2000},
    500
};

adk::BoundedServo servo (config);
```

`BoundedServo::initialize()` validates the safe position but remains
`Inactive`. `command(position)` either produces a `Position` intent and pulse
or rejects the command without changing the previous accepted intent.
`snapshot()` exposes intent, complete status, position, and pulse width.
`shutdown()` returns the model to `Inactive`.

`ServoConfigurationRecord` provides a fixed 20-byte versioned encoding inside
24 bytes of capacity. It validates magic, version, length, CRC, calibration
semantics, and safe position while preserving the generation field. `load()` reports an
empty record as `NotInitialized`, an unknown version as `Unsupported`, and
corruption as `HardwareFailure`. It does not repair, widen, or silently clamp a
record. Before acquiring any resource, the canonical example encodes its
reviewed compiled configuration and decodes and compares the complete result.
This exercises the record boundary in memory; EEPROM or another persistent
storage transport is deliberately deferred.

## Owning pulse endpoint

`MegaTimer5ServoPulseIo` programs D44/OC5C directly. It does not hide the
global Arduino Servo library behind the resource registry.

```cpp
adk::ExternalPowerDomainGate powerGate;
adk::MegaTimer5ServoPulseIo  pulseIo;
adk::ServoOutput             pulseOutput (
    runtime.resources (),
    pulseIo,
    powerGate,
    adk::MegaTimer5ServoPulseIo::signalPin,
    1000,
    2000,
    adk::MegaTimer5ServoPulseIo::timer);
```

`ExternalPowerDomainGate` is procedural permission to issue a pulse. It does
not sense or switch the external rail. This distinction allows TP-S to be
verified while the physical servo-positive switch remains open.

`ServoOutput::initialize()` transactionally claims D44 and Timer5, then
attaches an inert endpoint. `writePulse()` accepts only the configured and
absolute 544–2400 μs bounds, and only while command admission is open.
`shutdown()` disables Timer5, drives D44 low, returns it to high impedance, and
releases both claims. Any compare-register or output-connect failure performs
the same fail-closed teardown; commands then return `NotInitialized` until an
explicit shutdown/reinitialize cycle.

## Narrative example

The canonical example makes each button press advance through center, low,
center, and high. Its loop reads as the circuit does:

```cpp
if (!commandRequested (now))
{
    return;
}

const uint16_t position = positions[nextPosition];

if (!commandPosition (position))
{
    stopLogic ();
    return;
}
```

`commandPosition()` admits the command path, asks `BoundedServo` for a bounded
pulse, writes that pulse, then updates the independent position marker. On a
logic fault it revokes command admission, detaches the endpoint, and turns off
the indicators. The operator must still open the physical servo-power switch.

## Staged evidence

1. Keep servo-positive power physically open. Inspect polarity, common ground,
   the pointer arc, and the open disconnect.
2. Upload and reset. The example first validates the configuration record,
   acquires its resources, illuminates the middle marker, and emits the
   1500 μs safe command while servo power remains open.
3. D13 on means that startup sequence completed; it does not prove load power
   or motion.
4. Observe TP-S high time and 20 ms frame before pressing the button and while
   servo power remains open.
5. Set the admitted supply voltage and current limit from the exact servo's
   documentation. Clear the pointer arc, then deliberately close load power.
6. Observe TP-V, supply current, and the paper pointer. Record command marker
   and pointer separately at low, middle, and high.
7. Open load power first. Verify zero load current. Then run the logic shutdown
   exercise and verify TP-S stops and D44 becomes high impedance.

The first pointer endpoint is never found by driving into a stop. Establish a
narrow software envelope from documented bounds and no-load observations.

## CLI workflow

```sh
make host-test
make arduino-Lesson017BoundedServo
make size-check
make lessons
make lessons-check
make site
make site-check
```

Use `make boards` before upload and
`make upload EXAMPLE=Lesson017BoundedServo PORT=/dev/ttyACM0` with servo load
power open. The example emits no Serial data. `make monitor` and
`make serial-log` remain available for optional supporting records, but they
cannot replace TP-S, TP-V, current, marker, and pointer evidence.

Mega compilation currently measures 6,656 bytes of flash and 323 bytes of
static RAM with the repository toolchain. Compilation and host tests are not
physical verification.

## Deferred bench acceptance

Record the exact servo identity and markings; primary datasheet; pin order;
voltage and pulse range; selected supply and current limit; idle, movement, and
startup current; TP-S high time and frame; TP-V at rest and motion; low/middle/
high command-marker and pointer agreement; shutdown current; reset behavior;
instruments; deviations; reviewer; and date.

Until that record is complete, this lesson remains **host verified; hardware
acceptance open**.
