# Lesson 060 — dual-display timing desk

Status: **E0 deterministic project composition; combined powered display
fixture and bench acceptance open**

Energy class: **E0 copied controls, frames, commands, and receipts only**
Safety boundary: **no button endpoint, display pin, timer, interrupt, SPI bus,
chip-select pin, display module, supply, or powered circuit**

`DualDisplayTimingDesk` derives two presentation intents from one immutable
stopwatch snapshot:

`copied controls + supplied time → one stopwatch snapshot → two attributable display frames`

The four-digit side comes from Lesson 058. The matrix side comes from Lesson
059. The project owns both policies so it can preflight both complete frames
before committing either one. This makes their source meaning atomic, but it
does not make two physical displays change simultaneously and cannot roll
back bytes already accepted by a future transport.

## Stopwatch controls

The copied control envelope carries start/pause, lap, and reset evidence with
source identity, configuration revision, sequence, observation time, edge and
level consistency, and freshness. The complete envelope is validated before
any state changes.

Reset dominates every valid control combination. Pressing start/pause and lap
together is ambiguous and changes nothing. Held controls do not repeat.
Presentation backpressure never asks the caller to replay an accepted control
edge.

| Control edge | Stopped zero | Running | Paused |
|---|---|---|---|
| start/pause | start | pause and materialize elapsed time | resume |
| lap | retain zero | show a two-second lap snapshot while time continues | retain paused time |
| reset | canonical stopped zero | canonical stopped zero | canonical stopped zero |

The stopwatch reads no clock. It advances only from supplied time, validates
modular ordering, and rejects backward or exact-half-range time atomically.
Its display capacity is `9:59.9`; reaching that value saturates visibly and
stops instead of wrapping.

## One snapshot, two mappings

Stopped and running states show current elapsed time. Paused state shows the
materialized elapsed value. A lap press freezes both presentation frames for
exactly 2,000 ms while the internal running stopwatch continues. The lap
remains visible at the inclusive deadline; the next valid tick returns both
sides to current time.

The four-digit value is minute, seconds tens, seconds units, and tenths from
left to right. Decimal mask `0x0A` lights the leftmost separator and the
seconds-unit separator.

The matrix has two independent regions:

- The 28 perimeter pixels form a clockwise minute dial beginning at the
  top-left corner. Zero milliseconds lights none; the first millisecond lights
  the first pixel; later buckets use
  `1 + floor((elapsed % 60000) × 28 / 60000)`, capped at 28.
- The central 4-by-4 glyph reports stopped, running, paused, lap, or fault.
  Lesson 059 applies its fixed orientation only after this complete logical
  frame has been derived.

The two frames retain the same source snapshot generation. Each also has a
side-specific 32-bit FNV-1a digest over its domain label, complete fixed frame,
source generation, and presentation mode. Agreement compares both the digest
and the retained full frame; a digest never substitutes for structural
equality.

The digest byte order is part of the interface, not an implementation detail.
For the digit side, start with ASCII `ADK.DIGIT.FRAME.V1` without a trailing
NUL. For digit indices zero through three, append the one-byte numeric glyph
and then the one-byte diagnostic glyph. Append the decimal mask, an overflow
byte (`0x00` or `0x01`), the source snapshot sequence as four little-endian
bytes, the frame generation as four little-endian bytes, and the presentation
mode byte. For the matrix side, start with ASCII
`ADK.MATRIX.FRAME.V1` without a trailing NUL, then append rows zero through
seven, the same two little-endian 32-bit values, and the mode byte. Fold each
byte separately with FNV-1a offset `0x811c9dc5` and prime `0x01000193`.

Two literal witnesses make that contract testable across implementations:

- digit glyphs `{0, 1, 2, 3}`, diagnostic glyphs `{1, 2, 3, 4}`, decimal
  mask `0x0A`, overflow `true`, source sequence `0x01020304`, generation
  `0x11223344`, and mode `0x80` produce `0x80dc784f`;
- matrix rows `{0, 1, 2, 3, 4, 5, 6, 7}` with that same source sequence,
  generation, and mode produce `0x2887577e`.

## Bounded publication and receipts

Only one dual presentation generation may be outstanding. While it is
pending, supplied-time updates continue the stopwatch, report presentation
`ResourceBusy`, and leave both published intents unchanged. Once that
generation is accepted or faults, the next valid update freezes the newest
stopwatch snapshot and publishes the next coherent pair.

Each copied endpoint receipt identifies:

- the project owner, lifecycle, and configuration;
- the requested and accepted presentation generation;
- the reported complete logical frame and its digest;
- complete status and observation time; and
- whether the side accepted a blank request.

“Accepted” means that a complete logical digit bank or complete
recording-transport row sequence was admitted. It does not mean the digit bank
was visibly scanned, a MAX7219 was read back, or any pixel changed.

The presentation grace interval defaults to 100 ms and is configurable from 1
through 1,000 ms. One accepted side and one pending side remains pending
through the inclusive deadline. The next valid tick faults. Wrong content,
wrong digest, stale or crossed generations, a digit refresh loss, one-sided
failure, or grace expiry enters attributable disagreement, preserves
stopwatch history, and requests both displays blank.

## Fixed service order

One `update(envelope)` call is one bounded service opportunity. It:

1. validates the complete copied envelope;
2. ingests child receipts;
3. services at most one due digit transaction;
4. services at most one MAX7219 command;
5. evaluates grace and self-test state;
6. applies valid control edges once and advances the stopwatch; and
7. when no generation is outstanding, preflights and publishes the next
   post-control snapshot.

`controlStatus` is independent from `presentationDisposition`. A busy or
faulted presentation therefore cannot erase an accepted stopwatch control.
The caller must still service the project frequently enough to satisfy Lesson
058's four-millisecond digit-service limit.

## Self-test before ready

Initialization does not immediately claim the desk is ready. A deterministic
14-stage self-test publishes:

1. one common blank stage;
2. eight indexed stages pairing digit segments `a` through `dp` with matrix
   diagonal pixels;
3. four digit-select stages pairing one displayed `8` with the matching matrix
   column; and
4. one final common blank stage.

A stage advances only after both complete, correlated receipts match its
generation and expected side-specific frame. The 100 ms per-stage timeout is
inclusive; the next valid tick faults. Reset clears elapsed and lap state,
invalidates old receipts, and starts complete requalification. Ready zero is
the first ordinary generation after every self-test stage agrees.

This self-test proves E0 frame derivation, command sequencing, and copied
acknowledgement handling. It does not prove visibility, orientation, optical
agreement, brightness, refresh waveform, bus delivery, or physical blanking.

## Compile-only replay

The canonical Mega 2560 sketch uses named volatile result cells rather than
Serial as its observation path:

| Stage | Predict | Observe | Interpret |
|---:|---|---|---|
| initialize | both policies blank and self-test required | lifecycle, stage, and blank-request cells | E0 composition initialized; no endpoint acquired |
| self-test | both sides retain one common stage generation | expected frames, digests, and receipt cells | copied acknowledgements agree on one source |
| start | stopwatch runs from supplied time | phase, elapsed, and source-generation cells | no hidden clock advanced the result |
| lap | both frames hold one snapshot while elapsed continues | lap deadline and current/lap elapsed cells | presentation freeze did not pause the stopwatch |
| busy | controls remain admissible while one pair is pending | control status and presentation disposition | backpressure does not replay an edge |
| disagreement | one bad or late side requests common blanking | side, cause, generation, and blank cells | fault provenance remains attributable |
| reset | elapsed clears and self-test restarts | lifecycle and requalification cells | stale receipts cannot restore readiness |
| shutdown | no ordinary command remains active | shutdown and result cells | logical service stopped; no physical-dark claim |

Predict the complete copied values before each call and compare the named cells
with the deterministic host trace. Compilation establishes only that the E0
example fits the selected Mega toolchain.

## Deterministic proof

Project tests cover all eight control masks in every stopwatch phase, held
controls, malformed companion evidence, capacity saturation, lap boundaries,
reset, modular rollover, backward time, and exact-half-range rejection.

Presentation tests cover every minute-dial bucket, all status glyph row bytes,
one outstanding generation, both receipt orders, inclusive grace, wrong frame
and digest, stale and crossed generations, digit refresh loss, partial MAX
failure, one-sided and simultaneous faults, blank requests, restart, shutdown,
generation exhaustion, and byte-identical replay. Self-test tests cover every
stage, timeout, failure direction, and reset-driven requalification.

The exact no-LTO AVR resource gate records linked flash, static SRAM, full
object composition, conservative synchronous stack, residual SRAM, public
value sizes and traits, and toolchain fingerprints. The Lesson 060 targets are
24 KiB flash, 2,048 bytes static SRAM, 640 bytes synchronous stack, and a
640-byte object composition; hard ceilings are 32 KiB, 3,072 bytes, 896 bytes,
and 896 bytes. Final measured values must pass this gate before promotion.
Compiler measurements are not runtime stack-watermark, electrical, optical,
transport, or physical evidence.

## E1c remains open

At E0, resource-acquisition evidence is “no resources requested.” Safe-state
evidence is the copied common blank request and both child policies' logical
blank state. These are separate policy observations, and neither proves that a
powered fixture is dark.

Combined E1c work may begin only after the independent Lesson 058 digit fixture
and Lesson 059 MAX7219 fixture have passed their own E1 qualification. The
combined authoritative schematic and bench record must then establish:

- exact shared supply, grounding, pin, timer, interrupt, SPI, and chip-select
  ownership with transactional rollback;
- loaded current and rail behavior with both displays showing worst-case
  permitted frames;
- digit refresh latency while MAX commands are paced one at a time;
- self-test visibility, fixed orientation, brightness, ghosting, and optical
  agreement;
- injected one-sided failure, reset, restart, and observed common blanking;
  and
- separate physical-power removal, unpowered wiring inspection,
  resource-acquisition evidence, and safe-state evidence.

Do not combine unqualified modules merely because both E0 policies pass. A
software blank request, shutdown, destructor, or successful copied receipt is
not an emergency stop and is not evidence that either powered display is
dark.
