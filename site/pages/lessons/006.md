# Deterministic Simon

Status: **engine host verified; hardware adapter experimental**<br>
Energy class: **E1** — low-voltage buttons, current-limited LEDs, and one
passive piezo

Simon is the second integration checkpoint. Four buttons become one complete
`SimonInput`; the hardware-neutral engine returns output intent in a
`SimonSnapshot`. It never reads pins, drives cues, sleeps, allocates, or consults
a hidden clock.

```cpp
buttons[0].update (now);
buttons[1].update (now);
buttons[2].update (now);
buttons[3].update (now);

const adk::Status status = game.update (now, input);
const adk::SimonSnapshot state = game.snapshot ();
```

The HTML reference defines the interface boundary. The PDF supplies the full
four-button, cue-LED, RGB, and passive-piezo circuit; state diagram; golden
replay; fault matrix; current budget; and staged hardware acceptance procedure.

The canonical adapter emits a D13 acquisition-only pulse for 250 ms, keeps all
game outputs inactive through a 750 ms separator, then starts a fixed
120-second run window. At the deadline it stops every behavior output, holds a
250 ms inactive interval, releases all endpoints in reverse order, and remains
halted until reset. Near-simultaneous presses are physical chord evidence only;
exact simultaneity remains a host-replay fact.

The adapter also carries the published two-entry `One`, `Three` replay as a
bounded compile-time fixture. Build the identifiable bench artifact with
`--build-property compiler.cpp.extra_flags=-DADK_LESSON006_FIXED_REPLAY=1`;
the default value zero retains the seeded demonstration. Fixture value one
selects the PDF's exact timings and maximum sequence length as well as its
fixed source.

The PDF names every test point, uses one-at-a-time 10 kΩ/10 kΩ midpoint
fixtures for physical high-impedance evidence, records resistor-drop current
and aggregate bounds, and keeps acquisition, behavior, shutdown, reset, and
power removal separate. Physical acceptance remains pending until a named
operator and reviewer complete the card.
