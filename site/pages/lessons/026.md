# Telemetry packet evidence

Status: **host verified; hardware acceptance open**
Energy class: **E1** — USB-powered Mega and one resistor-limited evidence LED
Radio boundary: **compiled-in ADK-owned fixtures; no receiver or transmitter**

This lesson preserves the chain:

`packet bytes → integrity → accepted observation → local age → visible evidence`

`TelemetryPacketCodec` defines an exact 19-byte lab packet.
`ObservationTracker` then classifies sequence and freshness from local receipt
time. The packet is an ADK teaching format, not a decoded commercial radio
protocol. CRC-16 detects accidental corruption; it supplies no authentication,
confidentiality, provenance, or replay protection.

## Circuit and evidence

| Signal | Mega pin | Connection |
|---|---:|---|
| Acquisition | D13 | built-in LED |
| Observation evidence / TP-LED | D45 | D45 → 1 kΩ → LED anode; cathode → GND |
| Probe reference | GND | meter or logic-probe reference |

The sketch generates a deterministic 12-second fixture cycle:

| Evidence | D45 cadence |
|---|---|
| fresh, in order | one 1 s pulse |
| sequence anomaly or aging | two 150 ms pulses |
| stale | three 120 ms pulses |
| corrupt fixture | four 100 ms pulses |

The cycle accepts sequence 1, deliberately skips sequence 2 and accepts 3,
corrupts the next packet, stays silent until sequence 3 becomes stale, then
accepts sequence 4 after the cycle wraps. Gap, corrupt, stale, and
recovered-fresh states are therefore all observable.

D13 illuminates only after the tracker and both LEDs initialize. D45 reports
packet state. These are separate claims. Measure TP-LED against GND after
shutdown; a dark LED alone does not prove that the pin is released.

## Exact packet

All multibyte fields are big-endian. Signed value and exponent use two's
complement. The CRC covers bytes 0–16 and is stored high byte first.

| Offset | Bytes | Field |
|---:|---:|---|
| 0 | 1 | magic `0xAD` |
| 1 | 1 | version `0x01` |
| 2 | 2 | opaque source ID |
| 4 | 2 | sequence |
| 6 | 4 | remote observation milliseconds |
| 10 | 1 | telemetry kind |
| 11 | 1 | sample quality |
| 12 | 4 | signed value |
| 16 | 1 | signed decimal exponent |
| 17 | 2 | CRC-16 |

CRC-16/CCITT-FALSE uses polynomial `0x1021`, initial value `0xFFFF`, no
reflection, no final XOR, and covers bytes 0–16. The implementation and
golden-vector tests are authoritative if this summary ever diverges. Decode
requires an exact packet: truncation and trailing bytes are distinct. Failure
leaves the caller's destination unchanged.

A flipped value or timestamp bit with the old CRC produces `BadIntegrity`.
A changed magic, version, kind, or quality can be classified by that semantic
check first. Tests recompute CRC after deliberately changing a semantic field
when isolating `BadVersion`, `BadType`, or `BadQuality`. Every one-bit mutation
of a golden packet is rejected, but its exact rejection class follows this
precedence.

## Sequence and freshness

`SequenceState` distinguishes first, in-order, duplicate, forward gap, and
reordered observations using the documented 16-bit half-range rule. Duplicate
and reordered packets do not replace the accepted sample. A forward gap may
replace it while remaining visible.

The exact ambiguous delta `0x8000` is `Reordered`; it never replaces the
accepted observation.

Freshness uses `receivedAt`, supplied by the local receiver. The packet's
`observedMilliseconds` is retained as evidence but cannot make an old packet
fresh. This prevents a reversed, drifting, or future remote clock from
extending local trust.

The lesson thresholds are:

- fresh before 2,000 ms;
- aging from 2,000 ms through 4,999 ms;
- stale at 5,000 ms and later.

Exact boundary behavior and `millis()` wrap are deterministic host tests.

## Narrative run loop

```cpp
observePacket           (now);
verifyPacket            (now);
updateFreshness         (now);
showObservationEvidence (now);
```

The example creates runtime resources, LEDs, pure codec, and tracker in
dependency order. Setup acquires, configures, and starts. The loop observes a
scheduled fixture, verifies its exact bytes, updates local freshness, and
actuates D45. Serial is optional and does not control tuning or replay.

`TelemetryFixtureSchedule` owns the tested one-shot sequence of fixture
decisions; the sketch does not duplicate its timing policy.
`TelemetryEvidenceModel` applies the tested precedence
`fault → corrupt → stale → sequence/aging → fresh`. The four top-level calls
therefore describe actual work rather than forwarding to a second private
state machine. An unexpected execution fault enters the safe-off path; the
four-pulse fixture demonstrates packet corruption, not a claim that a failed
output can diagnose itself.

## Privacy and receive-only boundary

The fixtures use opaque source `26`, a harmless temperature sample, and no
device address, location, credential, or unnecessary payload. If a future
separate receiver example is proposed, record exact module identity, voltage,
frequency, ownership, and lawful use first. This lesson contains no RF
receiver, transmitter, tuning control, antenna, raw capture export, protocol
guessing, key recovery, replay, or command mapping.

## Predict, observe, interpret

1. Predict D13 will illuminate after all software and pin resources initialize.
2. Predict the D45 pattern for each fixture interval before uploading.
3. Observe D13 and TP-LED; compare pulse count and width with the table.
4. Interpret agreement as evidence that packet classification reached the
   circuit. It is not evidence of any radio or network behavior.
5. Invoke shutdown and measure TP-LED separately to test the safe state.
