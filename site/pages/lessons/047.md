# Lesson 047 — bounded logical step sequencing

Status: **E0 synthetic replay; energized motion and bench acceptance open**

Energy class: **E0 copied-command policy**
Safety boundary: **four-bit memory intent only**

`BoundedStepperSequence` turns an explicit copied command and caller-supplied
time into a bounded sequence of logical four-bit frames:

`copied command + explicit time → one due logical step → four-bit intent`

The policy owns no pin, endpoint, timer, interrupt, driver, supply, motor, stop
switch, or position sensor. Its logical position is only a volatile count from
initialization. It is not a measured angle, a physical position, or evidence
that a mechanism has been homed.

## The eight-frame sequence

The forward half-step order is fixed:

| Step | Four-bit intent | Set intent bits |
|---:|:---:|:---|
| 1 | `0001` | 1 |
| 2 | `0011` | 1 and 2 |
| 3 | `0010` | 2 |
| 4 | `0110` | 2 and 3 |
| 5 | `0100` | 3 |
| 6 | `1100` | 3 and 4 |
| 7 | `1000` | 4 |
| 8 | `1001` | 4 and 1 |

Reverse traverses the same ring in the opposite order. These bits identify
logical coil intent; they are not pin numbers, voltage levels, a ULN2003
wiring contract, or permission to energize a winding.

The policy prepares at most one due transition per call. When several
deadlines are overdue, repeated calls catch up one frame at a time while
retaining the original interval grid. It neither skips frames nor silently
stretches the requested interval.

## Commands, deadlines, and travel

A `StepperCommand` names a nonzero modular command ID, issue time, direction,
step count, interval, cancellation flag, and complete producer status.
Configuration bounds:

- the minimum and maximum allowed step interval;
- the maximum age of a live command;
- the minimum and maximum logical position; and
- whether the last logical frame may be retained after ordinary completion.

A moving command needs a nonzero step count. A stopped command needs zero
steps, but still carries an interval inside the configured range. Before
admission, the complete requested endpoint must fit inside the configured
logical range using widened arithmetic. A future issue time, invalid status
encoding, interval outside the configured range, command-ID regression or
half-range ambiguity, or impossible endpoint is rejected without changing the
committed snapshot.

Replaying the same ID and payload preserves the command identity rather than
replacing or restarting it. While motion is live, a later supplied `now` may
advance at most one due step or age the command into `Fault`; exact replay of
a terminal command is idempotent. A forward modular command ID may replace
live motion only when its complete endpoint is admissible. Changing a payload
under the same ID is rejected.

The first deadline is:

```text
issuedAt + stepInterval
```

An update immediately before that deadline does not step; an update exactly
at it advances one frame. The next deadline advances by the requested
interval, not by the caller's late arrival time. Wrap-safe comparisons preserve
the same rule across the 32-bit time rollover.

## Preview before commit

`preview()` validates a command and prepares its whole next snapshot without
mutating the policy. The opaque candidate is bound to the policy instance and
its current generation. `canCommit()` therefore rejects a candidate from
another owner, one prepared before a reset, or one made stale by a different
commit. A successful `commit()` publishes the candidate atomically.

This seam lets Lesson 048 check interaction and motion candidates together
before either policy advances. It is local transactional behavior, not a
generic transaction framework.

## Stop and all-off intent

Cancellation applies only to live motion and clears the four intent bits.
`stop(now)` is independent of the copied command, is idempotent, and clears
the bits immediately in policy state. Either cancelled state may admit a newer
explicit command; neither is a permanent stop latch. Command expiry or a
producer failure on an otherwise valid newly admitted command enters `Fault`,
clears the bits, and requires reset before new motion. Reset restores the
initialized, event-free, zero-position baseline.

`StepSequencePhase` makes each of these policy states explicit:

| Path | Phase | Four-bit intent | Recovery |
|---|---|:---:|---|
| initialize or reset | `Inactive` | `0000` | accept a valid command |
| admitted stopped command | `Holding` | prior frame only when hold is enabled; otherwise `0000` | admit a newer explicit command, stop, or reset |
| ordinary motion | `Moving` | one sequence frame | continue, replace, cancel, or stop |
| complete, no hold | `Complete` | `0000` | accept a new command |
| complete, hold enabled | `Complete` | final frame | accept a new command or stop |
| copied cancellation | `Cancelled` | `0000` | admit a newer explicit command or reset |
| independent stop | `Cancelled` | `0000` | admit a newer explicit command or reset |
| expiry or admitted producer failure | `Fault` | `0000` | reset before new motion |

The all-off value is only memory intent. It does not prove that a physical
driver stopped conducting or that motor power was removed. Even when
`holdAtRest` is true, this lesson makes no safe hold-current or temperature
claim.

## Synthetic replay

The canonical compile-only sketch replays forward motion, an admissible
replacement, reverse motion, copied cancellation, restart, completion, and an
independent stop. For each input it copies the command fields, operation
status, phase, disposition, direction, logical position, completed count,
four-bit intent, deadline, and policy status into named memory cells.

| Fixture | Predict | Observe in the host harness | Interpret |
|---|---|---|---|
| new forward command | admitted, no immediate step | `Moving`, zero completed, first deadline retained | admission is separate from a due transition |
| first deadline | one forward transition | `0001`, position `+1`, completed count `1` | exactly one frame advanced |
| overdue repeated calls | one transition per call | consecutive ring frames, unchanged interval grid | bounded catch-up does not skip |
| forward modular replacement | prior live command replaced atomically | new ID and `Replaced` disposition | complete endpoint was checked first |
| reverse transition | previous frame traversed | one reverse frame and position decrement | direction changes logical order only |
| cancellation or independent stop | all intent bits clear | `Cancelled`, `0000`, no deadline | stop clears active sequencing intent |
| command older than maximum age | fault before stepping | `Fault`, timeout status, `0000` | stale authorization cannot advance |
| reset | inert zero-position baseline | `Inactive`, `0000`, position `0` | this is not physical homing |

The named result cells are the non-Serial E0 observation path. The sketch
must be compiled but not run on a powered Mega or inspected through a powered
hardware debugger as E0 evidence. Initialization acquires no hardware
resource, while the all-off memory result is a separate policy-state check;
neither is physical acquisition or electrical safe-state evidence.

The measured complete Mega 2560 sketch uses **8,068 bytes of flash** against a
16,384-byte lesson budget and **1,053 bytes of static SRAM** against a
2,048-byte budget. Those measurements prove packaging and static size only.

## E2 motion gate

The likely later system is a 28BYJ-48 stepper with a ULN2003 carrier, but a
retail kit name does not establish an electrical identity. No driver, wiring
table, formal schematic, or powered procedure is published by this E0 lesson.

Energized motion remains E2-gated until the exact motor voltage and winding,
driver identity and topology, clamp connection, separate current-limited
supply, measured coil current, thermal and sequence limits, mechanical
restraint, independent stop and power removal, and physical-motion acceptance
are reviewed and recorded. A host trace, compiler result, or four-bit memory
mirror cannot satisfy any of those gates.
