# Lesson 031 — calibrated analog joystick

Status: **host verified; exact-revision wiring and physical acceptance open**  
Energy class: **E1** — USB-powered Mega, passive joystick, and
resistor-limited RGB indicator  
Safety boundary: **human input and low-voltage visual evidence only**

This lesson keeps observation, calibration, and operator intent separate:

`two raw ADC samples + raw switch → calibrated axes + debounced selection → RGB evidence`

`AnalogJoystick` owns two analog inputs and one active-low button. Each
`update(now)` samples X, then Y, then Select exactly once and publishes one
stable `AnalogJoystickSnapshot`. Raw ADC counts remain available beside the
normalized positions, so an application never has to mistake an interpretation
for the original observation.

The joystick family appears in both official Elegoo manifests in the
[authorized product-family set](../docs/inventory/AUTHORIZED_ELEGOO_SET.md).
That listing authorizes this host-side component and curriculum scope. It does
not establish the selected board's pin order, electrical ratings, axis
direction, or physical acceptance.

## Inspect first, then wire

Do not infer a pin order from module color, an internet photograph, or a
`KY-023` alias. With USB disconnected, identify the selected board's labels and
ground connection. Continue only when all five roles are unambiguous:

| Module role | Accepted label examples | Reference Mega connection |
|---|---|---|
| X wiper / `TP-X` | `VRx`, `X`, or `HOR` | A0 / D54 |
| Y wiper / `TP-Y` | `VRy`, `Y`, or `VER` | A1 / D55 |
| Select switch | `SW`, `KEY`, or `SEL` | D22, internal pull-up |
| Supply | `+`, `VCC`, or `5V` | 5 V only after the rating is established |
| Common | `-`, `GND`, or `0V` | Mega GND after an unpowered continuity check |

The reference procedure assumes the switch closes to ground. If the selected
revision does not, stop: changing the software pull policy does not qualify an
unknown circuit.

The separate common-cathode RGB witness uses D5, D6, and D7 for red, green, and
blue. Each pin connects through its own 330 Ω resistor to an LED anode; the
common cathode connects to Mega GND. A brief blue interval proves that all
resources were acquired. During normal observation, red means negative X,
green means positive X, and blue means centered X; Y controls brightness. An
accepted Select event produces a 200 ms white pulse before the axis preview
resumes. White intentionally drives all three resistor-limited RGB dies; the
bench worksheet must use the measured rail, resistor values, and LED forward
voltages rather than treating their nominal values as measurements. Color is
supporting evidence—the named test points, pulse duration, and direction
labels carry the same meaning without relying on color perception.

## Calibration contract

Each axis has an observed minimum, center, observed maximum, dead-zone width,
and optional inversion. Valid configuration requires:

- `observedMinimum < center < observedMaximum`;
- a center interval that leaves a nonzero span on both sides; and
- three distinct, supported, currently unclaimed Mega pins.

Values inside the inclusive center interval map to zero. Values below it map
linearly toward `-1000`; values above it map linearly toward `+1000`.
Intermediate arithmetic is 32-bit, the result is clamped before narrowing, and
inversion is applied last. `saturated` means the raw sample reached or exceeded
an observed endpoint. It is useful calibration evidence, not a diagnosis of an
electrical fault.

| Snapshot field | Meaning |
|---|---|
| `x.raw`, `y.raw` | the two ADC observations |
| `x.position`, `y.position` | calibrated values from -1000 through +1000 |
| `x.centered`, `y.centered` | raw sample lies in that axis's dead zone |
| `x.saturated`, `y.saturated` | raw sample is at or beyond an observed endpoint |
| `rawSelected` | latest undecounced switch level interpreted as selected/not selected |
| `selected` | stable debounced selection state |
| `selectEvent`, `releaseEvent` | transition accepted by the latest update |
| `status` | complete lifecycle or sampling result |

Axis orientation is configuration, not a universal property. Record which
physical direction produces positive X and positive Y, then use `inverted`
when the desired lesson orientation differs.

## Ownership and lifecycle

Construction is inert. `initialize()` validates the complete configuration and
board capabilities before claiming X, Y, and Select transactionally. If any
claim or endpoint setup fails, earlier work is rolled back in reverse order
and no later hardware operation occurs. Repeated initialization succeeds
without resampling or reconfiguring.

`shutdown()` is idempotent. It stops Select, Y, then X, releases all three
claims, and leaves the pins as inputs. The last raw and calibrated evidence
remains inspectable, but its snapshot status becomes `NotInitialized`.
Destruction performs the same shutdown. The type is neither copyable nor
movable.

## Narrative sketch

The canonical loop preserves the lesson's observe, decide, actuate vocabulary:

```cpp
void loop ()
{
    const adk::TimePoint now (millis ());

    const adk::AnalogJoystickSnapshot observation = observeJoystick (now);

    if (!observation.status.ok ())
    {
        stopSafely ();
        return;
    }

    const adk::Rgb preview = decidePreview (now, observation);

    if (!actuatePreview (preview))
    {
        stopSafely ();
    }
}
```

The component, not the sketch, owns calibration, dead-zone mapping, and button
debounce. Presentation consumes one snapshot and cannot trigger another input
read. Any failed update or RGB command enters the sketch's fail-dark
`stopSafely()` path. Serial may print the raw counts while calibrating, but it
is optional and never the only evidence path.

## Predict, observe, interpret

1. With USB disconnected, transcribe the selected module's labels. Verify
   ground continuity, the switch topology, three 330 Ω RGB resistors, and the
   common-cathode orientation. Do not connect an unresolved module.
2. Predict that neither RGB evidence nor input ownership exists before
   successful initialization. Restore USB and observe the brief blue ready
   interval. Interpret it only as evidence that every software owner acquired
   its resource.
3. Predict the centered raw counts and the `TP-X` and `TP-Y` voltages before
   touching the stick. Measure each test point relative to Mega GND, then
   compare the observations with the snapshot without treating an exact
   mid-rail value as universal.
4. Move through each axis separately. Predict its position sign and RGB
   direction label, observe the raw count, voltage, and witness behavior, and
   record the physical direction that reaches each endpoint.
5. Release the stick repeatedly. Predict zero inside the configured dead zone;
   interpret a persistent offset or endpoint saturation as calibration or
   circuit evidence that requires investigation.
6. Press, bounce, hold, and release Select. Predict that `rawSelected` changes
   first, each debounced event appears once, and the accepted press produces
   one 200 ms white pulse. Observe the RGB behavior separately from any
   optional Serial record.
7. Invoke shutdown. Predict immediate RGB darkness and no further sampling.
   Verify the input safe state with the documented weak-pull or instrument
   method; an extinguished LED alone does not prove high impedance.

Resource acquisition and electrical safe state are separate claims. Host
traces prove ordered reads, rollback, lifecycle, deterministic mapping,
debounce boundaries, timestamp rollover, and claim reuse. Only a recorded
bench procedure can establish the selected module's pinout, voltages,
directions, reset behavior, and shutdown state.

Stop and remove USB power for an unidentified label, wrong polarity, missing
resistor, hot part, unstable rail, out-of-rail test-point reading, unexpected
RGB behavior, or disagreement between the inspected board and this reference
table. Do not probe a powered board in continuity mode.
