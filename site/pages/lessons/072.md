# Lesson 072 — inert module-characterization bench

Status: **Published and host verified at E0; exact powered specimens and bench
acceptance remain open**

Energy class: **E0 copied descriptor and characterization evidence, supplied
time, semantic review intent, and caller-owned volatile record bytes only**
Safety boundary: **no module, ADC channel, comparator pin, pull resistor,
supply rail, potentiometer, stimulus, timer, interrupt, bus, display, clock,
storage medium, or powered fixture**

`InertModuleCharacterizationBench` composes the preceding two lessons without
silently promoting either one's evidence:

`one Lesson 070 descriptor + one terminal Lesson 071 run + one copied review script → presentation intent + one volatile 192-byte record image`

The project does not identify a board, acquire samples, control a sweep,
recompute characterization, calibrate a physical quantity, or certify a
module. It admits one complete immutable evidence envelope, reviews exactly
that envelope, and can prepare one canonical record in caller-owned memory.

## One atomic envelope

The bench accepts a `ModuleCharacterizationEnvelope`, not separately read
descriptor and result snapshots:

```cpp
struct ModuleCharacterizationEnvelope
{
    uint16_t envelopeRevision;
    ModuleCharacterizationEvidence evidence;
    uint32_t descriptorDigest;
    uint32_t evidenceDigest;
};
```

The authoritative descriptor appears exactly once, inside the Lesson 071
evidence. Admission compares the complete correlation chain:

- descriptor schema, identity, revision, declared specimen reference and
  revision, and declared electrical-evidence revision;
- declared channel topology, output stage, pull, rail, polarity, threshold
  control and direction, supply and signal ranges, raw domain, warm-up, and
  settling;
- envelope and characterization revisions;
- characterization lifecycle generation, session, run, leg counts,
  sequences, observation times, brackets, intervals, relation, and terminal
  disposition; and
- complete producer status plus descriptor and evidence digests.

A new result paired with an old descriptor, one altered revision, a changed
source, or independently sampled child state rejects atomically. Admission
checks lifecycle and configuration first, then structural envelope,
descriptor, and evidence validity, exact correlation, digest equality, and
finally terminal admissibility. A structural, correlation, or digest defect
rejects even when the fields resemble a producer fault. Only a fully
correlated, digest-correct terminal rejection is admitted as fault-dominant
domain evidence. Full fields remain authoritative. Digests detect accidental
correlation failures; they do not replace those fields or prove physical
identity.

Descriptor, evidence, and witness digests use CRC-32/ISO-HDLC over canonical
little-endian field encodings with the domain tags `ADK-MOD-DESC-1`,
`ADK-MOD-EVID-1`, and `ADK-MOD-WIT-1`. No raw C++ layout, padding, pointer, or
address enters a digest. Digest value zero is an ordinary valid value, never a
sentinel, including for `expectedDescriptorDigest`.

## Fixed fixture and lifecycle

`ModuleBenchConfig` fixes one declared fixture and one control source for the
complete lifecycle:

```cpp
struct ModuleBenchConfig
{
    uint16_t benchRevision;
    uint16_t envelopeRevision;
    uint16_t recordSchemaRevision;
    uint32_t expectedDescriptorId;
    uint16_t expectedDescriptorRevision;
    uint16_t expectedDescriptorSchemaRevision;
    uint16_t expectedDeclaredSpecimenRevision;
    uint16_t expectedDeclaredElectricalEvidenceRevision;
    uint32_t expectedDescriptorDigest;
    uint8_t expectedControlSourceId;
    uint16_t expectedControlSourceConfigurationRevision;
    Duration maximumControlAge;
};
```

The descriptor does not hot-swap. The bench does not autodetect a family,
vote among aliases, or accept whichever trace looks plausible. A reset
discards the saved compact snapshot, advances the nonzero lifecycle
generation, and returns to `Ready`; it does not change the configured
fixture. A new fixture requires a new configured object.

The public state is closed:

```cpp
enum struct ModuleBenchState : uint8_t
{
    Inert,
    Ready,
    ScriptActive,
    RecordPrepared,
    Fault,
    Shutdown
};
```

Construction is inert. `initialize()` validates configuration and enters
`Ready`. `beginSession()` is the only envelope-admission point. A fully
correlated terminal envelope enters `ScriptActive`; a structurally valid
terminal fault remains fault-dominant. `Shutdown` is terminal and inert.

## A five-step review, not another sweep

The script contains exactly five steps:

1. `InspectDeclaration`
2. `ReviewAscending`
3. `ReviewDescending`
4. `ReviewVerification`
5. `PrepareRecord`

The only commands are `None` and `Advance`. `Advance` moves to the next named
review step, but reaching `PrepareRecord` never writes caller memory. The
separate `prepareRecord()` call is valid only at that final step.

```cpp
enum struct ModuleBenchCommand : uint8_t
{
    None,
    Advance
};

struct ModuleBenchControl
{
    uint8_t sourceId;
    uint16_t sourceConfigurationRevision;
    uint32_t sessionId;
    uint32_t sequence;
    TimePoint observedAt;
    ModuleBenchCommand command;
    Status producerStatus;
};
```

Every control binds the configured source and source-configuration revision,
current session, sequence, observation time, command, and producer status.
Changed duplicates, regressions, gaps where required, future controls, stale
controls, and exact modular half-range ambiguity reject without mutation.
The bench uses supplied time; it owns no clock and performs no waiting.

| State | `None` | `Advance` | direct `prepareRecord()` | direct `reset()` |
|---|---|---|---|---|
| `Ready` | idempotent | invalid | invalid | `Ready`, generation + 1 |
| `ScriptActive`, before final | idempotent | next named step | invalid | `Ready`, generation + 1 |
| `ScriptActive`, final step | idempotent | remains final | prepare record | `Ready`, generation + 1 |
| `RecordPrepared` | idempotent | invalid | idempotent and byte-identical | `Ready`, generation + 1 |
| `Fault` | invalid | invalid | invalid | `Ready`, generation + 1 |
| `Shutdown` | not initialized | not initialized | not initialized | not initialized |

There is no second begin-leg, finish-leg, acquisition, export, or
acknowledgement surface. Lesson 071 already owns characterization. Lesson 072
reviews its terminal evidence.

## Public API

The coordinator is noncopyable, nonmovable, heap-free, callback-free,
clock-free, and hardware-free:

```cpp
struct InertModuleCharacterizationBench
{
    explicit InertModuleCharacterizationBench (
        const ModuleBenchConfig& config) noexcept;

    Status initialize     (TimePoint now) noexcept;
    Status beginSession   (
        TimePoint now,
        uint32_t sessionId,
        const ModuleCharacterizationEnvelope& envelope) noexcept;
    Status applyCommand   (
        TimePoint now,
        const ModuleBenchControl& control) noexcept;
    Status prepareRecord  (
        TimePoint now,
        ModuleCharacterizationRecordImage& output) noexcept;
    Status reset          (TimePoint now) noexcept;
    Status shutdown       (TimePoint now) noexcept;
    Status result         (ModuleBenchResult& output) const noexcept;
};
```

`ModuleBenchResult` stays compact. It reports lifecycle and session identity,
state, step, run identity, both envelope digests, comparator relation,
presentation, record-prepared state, and status. It does not duplicate the
descriptor, characterization evidence, or envelope.

## Fault-dominant presentation

Presentation is semantic intent rather than a display driver:

```cpp
struct ModuleBenchPresentationIntent
{
    ModuleBenchScriptStep step;
    ModuleBenchState state;
    bool faultDominant;
    ModuleComparatorRelation relation;
};
```

A malformed envelope rejects before a session begins. A terminal unhealthy
Lesson 071 result remains visible as typed evidence. Producer failure,
identity mismatch, stale evidence, chatter, no-transition evidence,
endpoint-only rail evidence, or analog/comparator disagreement cannot be
hidden by a plausible bracket or raw value.

Healthy samples at either rail remain ordinary evidence. `AtLowerRail` and
`AtUpperRail` mean only that Lesson 071 terminalized an endpoint-only run.
They never become `OpenLike`, `ShortLike`, damaged-module, safe-to-connect, or
physical root-cause diagnoses.

Raw ADC codes also remain raw codes. The bench does not convert them into
temperature, light, sound, gas concentration, distance, touch capacitance, or
another physical unit. Such a conversion needs its own justified calibration
contract.

## One exact volatile record

`prepareRecord()` can produce one
`ModuleCharacterizationRecordImage`, exactly 192 bytes:

```cpp
struct ModuleCharacterizationRecordImage
{
    static constexpr uint8_t version = 1;
    static constexpr uint16_t size = 192;
    uint8_t bytes[size];
};
```

The bench derives one compact semantic record, stages the complete image,
validates it, and only then copies it to caller storage. Early or failed
preparation leaves the output image and bench state byte-identical. Repeated
preparation in `RecordPrepared` returns the same bytes.

`ModuleCharacterizationRecordCodec` is the only encoder and decoder:

```cpp
struct ModuleCharacterizationRecordCodec
{
    Result<uint16_t> encode (
        const ModuleCharacterizationRecord& record,
        MutableByteSpan output) const noexcept;
    ModuleCharacterizationRecordValidity decode (
        ByteSpan image,
        ModuleCharacterizationRecord& output) const noexcept;
};
```

Decode checks exact span size, framing, CRC, semantic and canonical fields,
then performs one staged assignment. `BadLength` means only a span other than
192 bytes. `BadFraming` means wrong magic, version, or encoded length.
`BadIntegrity` means a CRC mismatch. `BadSemanticValue` means the CRC is valid
but a semantic or canonical field is defective. Decode leaves its output
unchanged on every failure.

Encode validates semantics before capacity, stages and zeros all 192 bytes,
calculates CRC last, and copies only on success. Invalid semantics return
`InvalidArgument`; short output returns `CapacityExceeded`; bytes after byte
191 in a larger output span remain untouched.

The byte format is normative:

| Bytes | Content |
|---:|---|
| 0–3 | ASCII `ADMC` |
| 4 | version |
| 5–6 | length = 192 |
| 7–10 | record-schema and bench revisions |
| 11–18 | lifecycle generation and session ID |
| 19–32 | descriptor ID/revision and declared specimen/electrical-evidence provenance |
| 33–39 | topology, output, pull, rail, polarity, threshold control, and direction |
| 40–61 | declared supply/signal/raw ranges and warm-up/settling declarations |
| 62–74 | run identity, characterization generation/revision, and three leg counts |
| 75–104 | ascending and descending compact transition brackets |
| 105–119 | guaranteed-inactive, guaranteed-active, and ambiguity intervals |
| 120 | comparator relation |
| 121–136 | first, last, and two offending witness digests |
| 137–152 | first/last sequences plus descriptor/evidence digests |
| 153–156 | terminal state, reason, status, and script step |
| 157–163 | descriptor schema, envelope revision, source, and source-configuration revision |
| 164–189 | reserved zero |
| 190–191 | CRC-16/CCITT-FALSE over bytes 0–189 |

All multibyte values are little-endian. CRC-16/CCITT-FALSE uses polynomial
`0x1021`, initial value `0xffff`, no reflection, and final XOR `0x0000`.
Changing field order, width, meaning, or canonical absence is a schema change.

The compact image cannot reconstruct the complete envelope or all sampled
points. Its domain-separated digests bind the authoritative evidence while
the bracket and interval summaries support review. `recordPrepared` means
only that bytes exist in caller memory. It does not mean saved, written,
flushed, durable, recoverable, qualified, or accepted.

Codec semantics require valid enum and status encodings, required nonzero
revisions and identities, a structurally valid reconstructed descriptor,
counts from 0 through 16, and canonical absent brackets and intervals.
Present brackets must be in-domain, change assertion state, and carry
unambiguously forward nonzero sequences. Intervals must be ordered and
in-domain, and guaranteed-active and guaranteed-inactive intervals cannot
overlap. Empty evidence requires zero first and last sequence summaries;
nonempty evidence requires nonzero equal-or-unambiguously-forward summaries.
Terminal state is either `Complete` with `None` and `Ok`, or `Rejected` with a
non-`None` reason and its retained status. The script step is exactly
`PrepareRecord`, and reserved bytes are zero. Digest fields, including zero,
are opaque exact values and are not recomputed by the compact codec.

The image intentionally omits `terminalLeg`, current `legId`, observation
times, control ordinals, directions, complete points, and full producer
statuses. Those fields remain authoritative in Lesson 071 evidence and are
bound indirectly by `evidenceDigest`; decoding the compact image cannot
reconstruct a Lesson 071 result.

## Predict, observe, interpret

Before each replay action, predict the bench state, exact script step,
fault-dominant flag, comparator relation, and whether record preparation is
eligible.

Observe the named caller-owned result and image cells: lifecycle generation,
session ID, state, step, run ID, descriptor and evidence digests, relation,
presentation intent, `recordPrepared`, status, record bytes, and codec
validity. These values are the E0 non-Serial observation path. Optional
Serial output may summarize them but is not the evidence.

Interpret script progress as proof of deterministic review behavior only.
Interpret an unchanged image after rejection as proof of atomic value
semantics only. Interpret a valid `ADMC` image as a well-formed record of the
supplied copied evidence, never as proof that a module was connected,
powered, stimulated, calibrated, or safe.

## Failure interpretation

| Observation | Meaning at E0 | Next check |
|---|---|---|
| `beginSession()` rejects | Envelope, descriptor, run, source, revision, status, or digest correlation failed | Compare every authoritative field before inspecting numeric plausibility |
| `Fault` with plausible brackets | Terminal unhealthy evidence dominates the copied numeric summary | Inspect producer status, characterization reason, relation, and witness attribution |
| Script does not advance | Control was absent, invalid, stale, out of order, or not attributable to this session | Compare source/configuration, session, sequence, time, and command |
| Early preparation rejects | The review has not reached `PrepareRecord` | Preserve the image and advance only through named steps |
| Decode reports framing failure | Magic, version, or encoded length is noncanonical | Reject the complete image |
| Decode reports integrity failure | The CRC does not match bytes 0–189 | Reject the complete image; do not repair it silently |
| Decode reports semantic failure | A CRC-valid enum, identity, bracket, interval, terminal relationship, script step, or reserved byte is noncanonical | Reject the complete image |
| `recordPrepared` but no file appears | Correct E0 behavior: no persistence endpoint exists | Treat the bytes as volatile caller memory |
| Shutdown intent is inert | Policy work is disabled | Do not infer physical power removal or a safe electrical state |

## No circuit at E0

There is no wiring section because Lesson 072 owns no circuit. Its resource
claim is zero pins, zero ADC channels, zero comparator inputs, zero timers,
zero interrupts, zero buses, zero supplies, zero displays, zero storage
endpoints, and zero powered devices.

The compile-only Mega replay uses synthetic copied values and writes named
result and record cells. Resource-acquisition evidence is separately zero
endpoint and registry calls. Safe-state evidence is the absence of hardware
intent. Neither proves that an external fixture is disconnected, unpowered,
or electrically safe.

The canonical Mega replay executes the real Lessons 070 and 071 paths, admits
one atomic envelope, advances all five review steps, and retains two
simultaneous 192-byte images for encode/decode comparison. The measured
resource evidence is:

| Metric | Measured | Target | Hard limit |
|---|---:|---:|---:|
| ordinary sketch flash | 24,860 B | 24 KiB | 32 KiB |
| ordinary sketch static SRAM | 1,998 B | 2,048 B | 3,072 B |
| isolated no-LTO flash | 27,354 B | 24 KiB | 32 KiB |
| isolated no-LTO static SRAM | 2,002 B | 2,048 B | 3,072 B |
| isolated synchronous stack | 740 B | 768 B | 1,024 B |
| bench coordinator | 436 B | 512 B | 768 B |
| one record image | 192 B | exactly 192 B | exactly 192 B |
| simultaneous images | 384 B | exactly 384 B | exactly 384 B |
| residual Mega 2560 SRAM | 5,322 B | at least 4,096 B | at least 3,072 B |

The exact no-LTO flash result is 2,778 B above its target and 5,414 B below
its hard limit. Independent design review accepted that target miss without
weakening the evidence model. Every other target and every hard gate passes.
The results are bound to compiler, core, flags, sources, fixture, and call
graph fingerprint
`b56bd8ef7a12328b80ad613b2a8b41f2cbde8e6fbd5ff0aa408208f50e3b6679`;
any change to those inputs makes the review stale.

## Open powered acceptance

No exact module is qualified by this lesson. Future E1 work must separately
record the exact specimen and revision, authoritative or verified circuit
evidence, pinout, supply limits, current, pull rail, ADC reference and source
impedance, output levels, inactive behavior, backfeed behavior, bounded safe
stimulus, and named AO/DO/VCC/GND test-point predictions and observations.

Resource acquisition and safe-state evidence remain separate checks. A future
presentation endpoint needs its own ownership, startup, refresh-loss, fault,
and shutdown evidence. A future persistence adapter needs prepare, write,
flush, verification, interrupted-write recovery, removal, capacity, and
power-loss evidence. None can be inferred from the volatile image.

The E0 family allowlist supports copied planning evidence for declared
low-voltage analog/comparator fixtures in the light, sound, Hall,
thermal, flame/radiant, Metal Touch, vibration, and obstacle families.
It does not establish identity or permission to energize a board. Gas/heater
modules, lasers, physiological modules, register devices, emitters, unknown
boards, mains, high voltage, flame, ignition, hot targets, pyrotechnic
ignition, launcher control, and unknown-protocol replay are outside this
boundary.
