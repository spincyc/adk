\section{Mission and success criteria}

Build a reaction timer with a debounced button and a diagnostic LED. A press and
release start the trial, a ready pulse precedes a configured dark wait, and the
cue then remains on for a configured response window. A press during the dark
wait is premature; no press before timeout is a failure. Given the same immutable
configuration and timestamped observations, the program must reproduce the same
states and result.

By the end, you can:

\begin{itemize}
  \item trace an active-low button and an active-high LED from pin to ground;
  \item distinguish a raw electrical sample from a debounced state and edge;
  \item explain why time is supplied to \texttt{update()} instead of read secretly;
  \item replay a bounce trace and predict its single stable press event;
  \item test premature presses, timeout, rollover-safe elapsed time, and shutdown;
  \item collect a Mega 2560 acceptance record without calling observation proof of timing accuracy.
\end{itemize}

\warningbox{Disconnect USB and every other power source before changing wiring.
Use a 330\(\Omega\) series resistor with the external LED. Do not connect an
output directly to ground or 5\,V. The button circuit below uses the Mega's
internal pull-up: do not add an external 5\,V jumper. Stop immediately for heat,
odor, unexpected brightness, repeated resets, a rail outside the board-specific
accepted range, or current above the precomputed limit. Software shutdown is
not an emergency stop: remove USB power if any stop condition occurs.}

\section{Ownership and lifetime}

Construction records configuration but does not touch hardware. Initialization
claims each pin and configures it. Shutdown is idempotent. The output becomes
high impedance; the input releases its pull-up and claim. Destruction calls
shutdown, including when a caller using exceptions unwinds through ADK code.
ADK itself neither throws nor allocates.

\begin{lstlisting}[style=adkcpp]
adk::ResourceRegistry resources;
adk::DigitalOutput    cue       (resources, 8, adk::Level::Low);

adk::Button trigger
{
    resources,
    adk::ButtonConfig
    {
        22,
        adk::Pull::Up,
        adk::Level::Low,
        adk::Duration (20)
    }
};

adk::ReactionTimerConfig timerConfig;
timerConfig.readyDuration   = adk::Duration (1000);
timerConfig.waitDuration    = adk::Duration (2000);
timerConfig.responseTimeout = adk::Duration (1500);
timerConfig.resultDuration  = adk::Duration (1000);

adk::ReactionTimer timer (timerConfig);

const bool cueReady    = cue.initialize     ().ok ();
const bool buttonReady = trigger.initialize ().ok ();
const bool timerReady  = timer.initialize   ().ok ();

if (!(cueReady && buttonReady && timerReady))
{
    trigger.shutdown ();
    cue.shutdown     ();
    return;
}
\end{lstlisting}

This endpoint-focused listing uses the exact supported API. The
compile-authoritative example directory
\texttt{examples/}\allowbreak\texttt{Lesson003ReactionTimer} uses D8 for the
external cue and D13 for an independent acquisition pulse, matching this
lesson. Notice the aligned calls and explicit \texttt{ok()} checks.
\texttt{ReactionTimer} is a pure state owner; the GPIO owners perform hardware
cleanup. Holding the D22 button for three seconds reaches the controlled
shutdown fixture: D8 and D13 are first commanded LOW for 250\,ms, then D8,
D13, and D22 become high impedance. No callback runs during cleanup.

\section{Raw, stable, and event are different facts}

A switch contact may alternate several times before settling.
\texttt{rawPressed()} reports the latest interpreted candidate.
\texttt{pressed()} changes only after the candidate state has remained unchanged
for the configured interval. \texttt{pressEvent()} and
\texttt{releaseEvent()} are non-consuming snapshots: every observer gets the
same answer until the next update.

At 1029\,ms, if LOW persisted, \texttt{pressed()} and \texttt{pressEvent()} are
both true. Calling \texttt{pressEvent()} twice still returns true. At the next
update, \texttt{pressEvent()} becomes false while \texttt{pressed()} remains
true. A stable release later produces one \texttt{releaseEvent()}.

\subsection{A precise debounce rule}

\begin{enumerate}
  \item Interpret the raw level using active-low or active-high configuration.
  \item If raw differs from the current candidate, replace the candidate and
        record \texttt{candidateSince = now}.
  \item If candidate differs from stable and
        \texttt{now - candidateSince >= debounce}, commit the stable state.
  \item Derive exactly one press or release snapshot from that stable transition.
\end{enumerate}

Unsigned elapsed subtraction makes the comparison safe across one clock
rollover, provided every configured interval is less than half the time range.
Do not compare absolute deadlines with \texttt{now >= deadline}.

The button arms its press event only after a stable release, so a button held
during initialization cannot start a trial. \texttt{AwaitRelease} also requires
release before the ready phase. Only debounced events count. The cue timestamp
and LED snapshot belong to the same state transition:

\[
    reaction = pressTimestamp - cueTimestamp.
\]

Do not turn on the LED in one update and record the start in a later update.
The measured value then includes an undocumented scheduling error. This first
implementation uses a fixed \texttt{waitDuration}; a later randomized adapter
must choose that value before construction and record its generator version and
seed. It must not hide randomness inside \texttt{ReactionTimer}.

\section{Reference update order}

\begin{lstlisting}[style=adkcpp]
void loop ()
{
    const adk::TimePoint now (millis ());

    trigger.update (now);
    const adk::Status timerStatus = timer.update (now, trigger);

    const adk::ReactionTimerSnapshot state = timer.snapshot ();
    const adk::Level level = state.ledOn
                           ? adk::Level::High
                           : adk::Level::Low;
    const adk::Status outputStatus = cue.write (level);

    if (!(timerStatus.ok () &&
          outputStatus.ok ()))
    {
        trigger.shutdown ();
        cue.shutdown     ();
    }
}
\end{lstlisting}

All observers see one coherent update. Input sampling precedes behavior; behavior
precedes output. Reporting comes last in the canonical example. Reordering those
phases can introduce a one-update disagreement between the LED and recorded
start time. The full canonical sketch additionally checks the three-second D22
hold after sampling and before advancing the timer. That fixture is intentionally
reachable from every running state and is not evidence of an emergency stop.

\section{Mega 2560 procedure}

This is an E1 experiment. Before creating a physical run record, an operator
and an independent reviewer must accept the exact identity card, schematic,
current calculation, meter method, and stop limits below. Host replay and
compilation remain valid while physical acceptance remains pending.

\begin{enumerate}
  \item Record the complete identity card: repository commit, sketch hash,
        Arduino CLI and AVR core versions, FQBN, exact Mega board specimen,
        USB source/current limit, switch specimen, LED part/color/polarity and
        rating source, measured resistor value, jumper set, meter and probe,
        operator, reviewer, date, and bench-run ID.
  \item Disconnect power. Build the exact schematic and check every row in the
        connection table. Confirm the external LED resistor with a meter and
        record the accepted resistance range. Calculate the expected LED current
        from the accepted rail and LED forward-voltage bounds; accept it against
        the LED, per-pin, port, board, and USB-source limits before power.
  \item Compile the unmodified \texttt{examples/Lesson003ReactionTimer}. Record
        flash and static RAM. Compilation proves only that the program fits and
        type-checks.
  \item With probes fixed at the named test points, compile and upload the
        unmodified canonical sketch. Keep the button released through reset.
        Verify that TP-ACQ/D13 gives one 250\,ms acquisition pulse independent
        of the D8 timer indication. Verify TP-CUE/D8 pulses during Ready, remains
        LOW during Wait, and becomes HIGH for Cue.
  \item Press once after the cue. Verify exactly one result is reported and the
        cue changes according to the documented terminal state.
  \item Run three trials. Then deliberately press early; verify false-start
        indication and release gating.
  \item Hold the button through reset. Verify no immediate valid reaction.
  \item Run one trial without pressing after the cue. Record the visible
        timeout terminal state and its elapsed bound.
  \item Before the shutdown run, remove USB and install one fixture at a time.
        For D8, disconnect the LED branch and connect measured 10\,k\(\Omega\)
        resistors as 5\,V--10\,k\(\Omega\)--TP-CUE--10\,k\(\Omega\)--GND.
        Measure TP-CUE to GND and calculate driven-LOW, driven-HIGH, and
        released midpoint ranges using resistor tolerance, measured rail, and
        DMM input resistance. Repeat for D13 only after recording the exact
        board LED circuit and including its loading in the calculation. For
        D22, leave the switch released and connect the named DMM
        TP-BUTTON-to-GND; calculate the pull-up-active and post-shutdown ranges.
        Never install, move, or remove a fixture while powered.
  \item Hold D22 continuously for at least three seconds. Observe D8 and D13 LOW
        for the controlled 250\,ms interval. Without moving the fixed probes,
        use the accepted high-impedance test fixture to distinguish high
        impedance from a driven LOW at TP-CUE and TP-ACQ; record both results.
        At TP-BUTTON, release the switch after shutdown and use the same accepted
        weak-bias method to prove that D22 is high impedance with its internal
        pull-up disabled. Never use a low-resistance forced-voltage test.
  \item Press reset and repeat the acquisition and nominal-cue observations.
        Reach controlled shutdown again and repeat all three safe-state
        measurements; reset is a new run, not proof that the prior shutdown
        persisted.
  \item Remove USB power without moving wiring. Record 0\,V at TP-CUE,
        TP-ACQ, TP-BUTTON, and the 5\,V rail relative to GND. Only then inspect
        or reconfigure the circuit and record the final component disposition.
\end{enumerate}

\section{Analysis and extension}

\begin{enumerate}
  \item Show the reaction calculation for each hardware trial. Report timer
        resolution; do not report more precision than the clock supplies.
  \item Does debounce add 20\,ms to the reported reaction? State whether the
        design records the first raw candidate or stable-transition timestamp,
        then defend that policy:\\[3pt]
        \blank{0.92\linewidth}.
  \item Add a second diagnostic output without changing \texttt{Button}. Use it
        to distinguish Ready, Wait, Cue, Success, and Failure.
  \item Replace the LED cue with a semantic \texttt{MonoLed}. Which layer should
        know that HIGH means luminous? \blank{3.4in}.
  \item Design a two-button choice reaction test. Define simultaneous stable
        presses as an explicit invalid chord; do not depend on update order.
  \item Design a replay file containing configuration, timestamps, button
        observations, and expected snapshots. Then specify the generator version
        and seed fields a future randomized wait adapter would add.
\end{enumerate}
