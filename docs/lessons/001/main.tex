\section*{Safety boundary}

Use only the board's factory-installed LED and USB power. Work dry, on a
nonconductive surface. Disconnect USB, barrel power, \texttt{VIN}, batteries,
shields, and every lead before inspection. Proceed only when the board and
cable are undamaged and no header pins touch.

\textbf{Stop immediately} for heat, smoke, odor, unexpected power flicker,
repeated USB disconnects, or a loose connector. Disconnect upstream power.
Do not touch a hot board or retry a damaged one. Label it \textsc{do not use}.

\begin{checkpoint}{all power removed before inspection}
\checkbox\ dry board \quad \checkbox\ clear headers \quad
\checkbox\ sound cable \quad \checkbox\ no other power source
\end{checkpoint}

\section*{1. Separate a command from an electrical state}

A digital output actively drives a pin near ground for \texttt{Low} or near
the board supply for \texttt{High}. High impedance, written \texttt{HiZ},
means the output driver is disconnected. It is not another voltage level.
An unconnected high-impedance pin may float.

\section*{2. Read the ownership contract}

ADK treats the pin as a resource, not a global integer. Construction produces
an inert object. \texttt{initialize()} claims the pin and configures it
transactionally. \texttt{write()} changes only an initialized, owned output.
\texttt{shutdown()} is idempotent, selects input mode, and releases the pin as
high impedance.
Destruction calls shutdown, so stack unwinding in an exception-enabled host
still cleans up even though ADK does not throw internally.

\begin{center}
\begin{tikzpicture}[>=Latex,node distance=11mm,
    state/.style={draw,rounded corners,fill=soft,minimum width=37mm,
                  minimum height=11mm,align=center}]
    \node[state] (inert) {inert\\unclaimed, \texttt{HiZ}};
    \node[state,right=of inert] (active) {active\\claimed, driving};
    \draw[->,thick] (inert) to[bend left=16]
        node[above]{successful \texttt{initialize()}} (active);
    \draw[->,thick] (active) to[bend left=16]
        node[below]{\texttt{shutdown()} or destructor} (inert);
    \draw[->] (inert) edge[loop left] node[left]{failed initialize} (inert);
    \draw[->] (active) edge[loop right] node[right]{\texttt{write()}} (active);
\end{tikzpicture}
\end{center}

\begin{tabularx}{\linewidth}{@{}lXX@{}}
\toprule
Operation & Success & Failure or repetition\\
\midrule
construct & inert; no hardware access & not applicable\\
\texttt{initialize()} & claim, initial level, output mode & invalid or busy; remain inert\\
\texttt{write(level)} & drive requested level & report status; preserve contract\\
\texttt{shutdown()} & input mode, \texttt{HiZ}, release & repeated call is harmless\\
destruct & performs shutdown & never throws\\
\bottomrule
\end{tabularx}

\section*{3. Inspect the experimental first-class interface}

This interface is host-verified but still experimental; it is not yet a
stable supported release. \texttt{Runtime} owns the resource registry shared
by components. The canonical complete example is
\texttt{Lesson001DigitalOutput.ino} in its matching \texttt{examples}
directory.

\begin{lstlisting}[style=adkcpp]
adk::Runtime       runtime;
adk::DigitalOutput output (runtime.resources (), LED_BUILTIN,
                           adk::Level::Low);

adk::Status status = output.initialize ();
if (status != adk::Status::Ok)
{
    // Stay inert. Report the explicit status.
}

status = output.write (adk::Level::High);
status = output.write (adk::Level::Low);
output.shutdown ();
\end{lstlisting}

\textbf{Why no implicit setup?} A constructor cannot return a status without
exceptions. Explicit initialization makes an invalid pin or resource conflict
observable. RAII still guarantees cleanup after successful acquisition.

\textbf{Why an explicit initial level?} Setting the output latch before enabling
the output driver avoids a brief unintended pulse. For the board LED, inactive
is low. A generic output's safe electrical endpoint is high impedance.

\section*{4. Build evidence on the host first}

The repository's fake Arduino functions record hardware calls as an ordered
trace. Host tests are fast, deterministic, and require no connected board.
This excerpt follows the assertions in \texttt{tests/test\_io.cpp}.

\begin{lstlisting}[style=adkcpp]
fake::reset ();
adk::ResourceRegistry resources;
{
    adk::DigitalOutput output (resources, 13);

    require (output.initialize () == adk::Status::Ok,
             "output initialization");
    require (output.write (adk::Level::High) == adk::Status::Ok,
             "output high write");
}
\end{lstlisting}

The test then checks this exact operation order: write \texttt{LOW}, select
\texttt{OUTPUT}, write \texttt{HIGH}, and finally select \texttt{INPUT} during
destruction. The claim is then available to a replacement object.

\section*{6. Run the board acceptance procedure}

\begin{enumerate}
    \item With all power removed, repeat the visual inspection.
    \item Connect only the USB data cable.
    \item Run \texttt{arduino-cli board list}. Copy the Mega's exact port.
    \item Upload the lesson sketch using the repository's documented target.
          Do not paste a port belonging to another device.
    \item Observe at least three complete cycles without touching conductors.
    \item Invoke or wait for the sketch's documented shutdown phase.
    \item Verify the LED becomes inactive. If instrumentation is available,
          measure pin mode safely; otherwise inspect the recorded host trace.
    \item Disconnect USB at the computer end.
\end{enumerate}

\section*{7. Debug with the smallest useful signal}

Digital output comes first because one spare pin can expose control flow
without a debugger. Assign meanings before running:

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
Pattern & Meaning\\
\midrule
steady inactive & waiting or safely stopped\\
one short pulse & update loop reached\\
two short pulses & input event accepted\\
slow repeated pulse & recoverable status\\
fast repeated pulse & stop and inspect\\
\bottomrule
\end{tabular}
\end{center}

Patterns are protocol, not decoration. Keep them deterministic, document the
time base, and test the trace. Never use delay-based debug output in code whose
timing contract forbids blocking.

\section*{8. Deliberately test misuse}

Run these on the host fake. Do not create shorts or faults on hardware.

\begin{enumerate}
    \item Construct two outputs for one pin. The second initialization must
          report a conflict without disturbing the first.
    \item Call \texttt{write()} before initialization. Record its status and
          confirm no platform operation occurred.
    \item Initialize with \texttt{NUM\_DIGITAL\_PINS}. Confirm
          \texttt{Status::InvalidPin}, an empty trace, and no resource claim.
    \item Call \texttt{shutdown()} twice. Confirm the second call is harmless.
    \item Leave scope while active. Confirm destructor cleanup matches explicit
          shutdown.
\end{enumerate}

\section*{9. Extension: polarity belongs above the endpoint}

\texttt{DigitalOutput} owns an electrical endpoint and speaks
\texttt{High}/\texttt{Low}. A later \texttt{MonoLed} composes it and speaks
\texttt{on}/\texttt{off}, accounting for active-high or active-low wiring.
Do not teach a generic pin that \texttt{High} always means ``on.''
