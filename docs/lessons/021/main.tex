\warningbox{Do not place a rover on the floor during initial work. Complete the
host replay and resistor-limited LED simulation before connecting a motor
driver. Select one exact driver and motor only after checking their primary
datasheets, supply limits, stall current, thermal limits, flyback strategy, and
truth table. A physical switch must remove motor-supply power. The software
stop button does not replace it. No person, animal, sharp tool, hot item, or
hazardous load may ride on the rover. Keep away from roads, stairs, hair, loose
clothing, and unattended operation.}

\section{Mission}

Compose range, wheel evidence, bounded motor intent, a static route, and an
operator stop into a deterministic supervisor:

\[
\{\text{range},\text{wheel edges},\text{start},\text{stop},\text{time}\}
\rightarrow \texttt{RoverController}
\rightarrow \{\text{left intent},\text{right intent},\text{mode}\}.
\]

The first rover is a host model. The second is six resistor-limited lamps that
show the two motor-driver interfaces without motor power. Only the final,
still-unaccepted stage connects a documented driver and raises the wheels
clear of the bench. These stages test the same route and supervisor.

By the end, you can:

\begin{itemize}
  \item explain why the supervisor emits intent but owns no pins or clock;
  \item replay the same inputs and obtain the same outputs byte for byte;
  \item show that stop dominates every driving and turning state;
  \item distinguish command evidence, electrical evidence, and physical motion;
  \item diagnose stale range, no initial motion, wheel disagreement, route
        timeout, and operator stop without relying on Serial;
  \item leave physical acceptance open without inventing a successful bench
        result.
\end{itemize}

\texttt{RoverController} is hardware-neutral. It receives complete observations
and produces complete intent. The canonical Mega sketch owns seven LED
components, two \texttt{MotorIntent} objects, an
\texttt{UltrasonicRanger}, and the controller. Its range echo and wheel edges
are deterministic simulations. Setup acquires every object before admitting
commands; shutdown first emits stopped intent, then makes the evidence outputs
inactive and releases them in reverse order.

\section{Supervisor contract}

Lessons 019 and 020 provide the landed \texttt{UltrasonicRanger} and
\texttt{MotorIntent} dependencies. The exact controller boundary is:

\begin{lstlisting}[style=adkcpp]
struct RoverInput
{
    RangeReading range;
    TimePoint rangeObservedAt;
    RoverWheelObservation leftWheel;
    RoverWheelObservation rightWheel;
    bool startEvent;
    bool stopRequested;
    TimePoint observedAt;
};

struct RoverControllerSnapshot
{
    MotorCommand leftMotor;
    MotorCommand rightMotor;
    RoverMode mode;
    RoverStopReason stopReason;
    Status status;
    RangeReading range;
    uint8_t routeIndex;
    bool stopDominated;
};

Status      initialize () noexcept;
Status      update     (const RoverInput& input) noexcept;
void        shutdown   () noexcept;
RoverControllerSnapshot snapshot () const noexcept;
\end{lstlisting}

The route contains only fixed records: drive, turn left, turn right, pause, or
finish; target wheel edges; maximum duration; and bounded duty. No allocation
or hidden clock is needed. A caller timestamp, observations, prior state, and
configuration determine each output.

\subsection{Stop dominance}

Evaluate the stop request before route progress. A stop request in
\texttt{Ready}, \texttt{Driving}, \texttt{Turning}, or
\texttt{ObstacleHold} selects zero-duty commands for both motors and enters
\texttt{Stopped}. A start/stop chord is a stop. Shutdown also emits stopped
intent. Sensor faults, stale range, initial-motion timeout, wheel disagreement,
route timeout, unexpected motion, and invalid time all request both motors
stopped.

\evidencebox{\textbf{Invariant to predict:} whenever
\texttt{stopRequested} is true, both applied commands are \texttt{Stopped} in
that same update. Stop also dominates a simultaneous start event. The two
\texttt{MotorIntent} objects apply those commands before the six LEDs present
their applied snapshots. A software trace proves the supervisor intent; the
enable witnesses prove only the presented logic state. Only a future physical
disconnect can prove removal of motor-supply energy.}

Restart is deliberate. Releasing stop or recovering a sensor does not resume
the route. Require stop release, fresh valid range, stationary evidence, and a
new start edge. Reset returns to inactive behavior and never restarts motion.

\section{Deterministic trace and replay}

Use one row per observation:

\begin{verbatim}
time,range-state,range-mm,left-total,right-total,start,stop-request,
rover-mode,left-command,right-command,route-index
\end{verbatim}

The host plant is an integer-only teaching model. It converts commands and
elapsed time into synthetic edge totals and scripted obstacle range. It can
inject wheel gain mismatch, start delay, stopping delay, and faults. It is not
a model of traction, stopping distance, supply sag, driver heating, or a
specific chassis.

\begin{enumerate}
  \item Run a fixed route twice with the same configuration and input rows.
  \item Compare every output field and serialized trace byte.
  \item Insert a stop request into each active state.
  \item Repeat at exact timeout boundaries and across timestamp rollover.
  \item Change one input only; predict the first output row that may differ.
\end{enumerate}

\toprule
Injected observation & Required decision & Circuit-native later evidence\\
\midrule
fresh clear range, matched edges & continue bounded route step & expected
direction lamps and enable waveform\\
range at stop threshold & obstacle hold, both duties zero & both enable
witnesses inactive\\
stale or invalid range & sensor fault, both duties zero & red fault cadence;
both enable witnesses inactive\\
one wheel supplies no new edges & motion fault after configured bound & red
fault state in the snapshot; all six witnesses inactive\\

\bottomrule

Serial may preserve or compare this trace. It never commands movement and is
never the only proof.

supply, H-bridge, motor, wheel, or battery is present.

\begin{enumerate}
  \item With USB removed, inspect every resistor and LED polarity.
  \item Predict all six lamps inactive at startup.
  \item Start the route and observe direction plus nonzero-duty enable intent.
  \item Request a reversal and observe the dead-time dark interval.
  \item Press software stop in every active mode; both enable lamps must become
        inactive immediately.
  \item Call shutdown; then measure D22--D27 against the named GND according to
        the endpoint's documented high-impedance procedure.
\end{enumerate}

The six witnesses deliberately encode commands rather than every controller
mode. A host snapshot distinguishes obstacle hold, fault, route completion,
and operator stop when each correctly presents the same all-dark output.

\subsection{Wheels-raised sequence}

\begin{enumerate}
  \item Remove USB and motor power. Raise and secure the chassis so no wheel can
        touch the bench. Remove fan blades or other attachments.
  \item Open the physical motor-power disconnect. Inspect against the exact
        schematic and verify polarity and shared-reference/isolation policy.
  \item Apply logic power only. Confirm both enable test points inactive during
        startup, reset, stop, fault, and shutdown.
  \item Close motor power at the lowest documented current-limited setting.
        Test one motor at the lowest useful duty for the shortest route step.
  \item Observe direction indicator, the named enable test point, a wheel mark,
        and the selected encoder evidence together. Disagreement is a stop
        condition.
  \item Test stop, stale range, blocked echo, one stalled wheel observation,
        and reset. Open the physical disconnect after every test.
\end{enumerate}

Do not infer safe floor behavior from a raised-wheel test. Traction, inertia,
stopping distance, chassis balance, radio loss, and environmental obstacles
have not been accepted.

\section{Further experiments}

\begin{enumerate}
  \item Minimize one replay that enters each fault using the fewest rows.
  \item Vary the host plant's left-wheel gain and find the exact configured
        mismatch boundary. Explain why it is not a physical tolerance claim.
  \item Change the existing route pause. Verify that synthetic wheel movement
        during the pause becomes explicit evidence rather than silently
        advancing the route.
  \item Design a separate stop indicator, then explain what evidence it adds
        beyond the six all-dark command witnesses.
  \item Propose a floor-test enclosure and stopping-distance protocol, but do
        not perform it until a separate reviewed acceptance plan exists.
\end{enumerate}
