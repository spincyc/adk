\section{Mission}

Build a deterministic boundary between a motion request and applied driver
intent:
\[
\text{operator request}\rightarrow\texttt{MotorIntent}\rightarrow
\texttt{MotorIntentSnapshot}\rightarrow\text{three evidence LEDs}.
\]
A request for the opposite direction never flips the direction signals while
enable is active. The controller first applies stop, waits through an explicit
dead-time deadline, then applies the opposite command. Stop dominates every
phase. Moving intent also requires an explicit admitted \texttt{PowerDomain};
the sketch admits it only after every evidence endpoint initializes.

\lessonbox{\textbf{Primary experiment.} The LEDs simulate H-bridge logic
inputs. No motor, motor supply, relay, or driver power stage is connected.
The exercise proves command timing; it does not prove torque, current,
rotation, or motor polarity.}

\subsection{Learning outcomes}

\begin{itemize}
  \item distinguish requested motion from applied electrical intent;
  \item explain why reversal has an all-inactive interval;
  \item replay transitions using caller-supplied time;
  \item observe direction, PWM enable, acquisition, and safe state separately;
  \item identify what must be measured before an E2 motor continuation.
\end{itemize}

\section{Deterministic controller}

\texttt{MotorCommand} contains a direction and duty. Stopped requires duty
zero; forward or reverse requires a nonzero duty no greater than the configured
maximum. The snapshot preserves both requested and applied commands.

\begin{lstlisting}[style=adkcpp]
void loop ()
{
    const adk::TimePoint now (millis ());

    observeOperatorRequest (now);
    decideMotorIntent      (now);
    actuateMotorEvidence   ();
}
\end{lstlisting}

The canonical example introduces the runtime, evidence endpoints, power gate,
then motor intent. Setup acquires, configures, and starts. The loop observes
one scheduled request, advances the explicit-time decision, then writes only
the \emph{applied} snapshot.

\subsection{Command rules}

\begin{enumerate}
  \item A valid stopped request applies immediately.
  \item A first moving request applies its direction and bounded duty.
  \item A same-direction duty change applies without dead time.
  \item An opposite request applies stop immediately and records a deadline.
  \item At the deadline, the pending opposite command becomes applied.
  \item Stop during dead time cancels the pending motion.
  \item Invalid input changes neither requested nor applied command.
\end{enumerate}

Hidden calls to \texttt{millis()}, blocking \texttt{delay()}, callbacks, and
heap-owned commands would make replay harder and do not belong in the
controller.

\section{Experiment A: acquire separately}

\textbf{Predict.} D13 illuminates only after the controller and all three
evidence outputs initialize. TP-F, TP-R, and TP-E remain inactive.

\textbf{Observe.} Reset the Mega. Record the D13 sequence and then measure the
three test points relative to the named GND reference.

\textbf{Interpret.} The D13 light supports successful acquisition. Low evidence
signals support the stopped electrical state. Neither observation substitutes
for the other.

\section{Experiment C: reversal dead time}

\textbf{Predict.} When reverse is requested during forward motion, enable
becomes zero and both direction LEDs go dark immediately. Reverse becomes
active only at the snapshot deadline.

\textbf{Observe.} Capture TP-F, TP-R, and TP-E on the same time base. Measure
from the falling enable edge to the first reverse/enabling edge.

\[
t_{\mathrm{dark}}=\blank{28mm}\qquad
t_{\mathrm{configured}}=\blank{28mm}\qquad
\mathrm{difference}=\blank{28mm}
\]

\textbf{Interpret.} A dark interval at least as long as the configured dead
time supports the reversal contract. It does not measure H-bridge switching
delay because no power driver is present.

\section{Deterministic test ledger}

\begin{itemize}
  \item invalid direction/duty/configuration before state change;
  \item stopped, first motion, same-direction duty change, and duty bounds;
  \item forward-to-reverse and reverse-to-forward dead time;
  \item just before, exactly at, and just after the deadline;
  \item stop and replacement requests during dead time;
  \item timestamp wraparound and long time jumps;
  \item stable snapshots and byte-identical replay;
  \item adapter acquisition rollback and resource reuse;
  \item inactive outputs during reset, fault, shutdown, and destruction.
\end{itemize}

\section{E2 continuation gate}

Do not connect motor power merely because the LED experiment passes. A future
supported continuation must select one H-bridge module and cite its primary
datasheet. Record:

\begin{itemize}
  \item motor stall current at the chosen current-limited supply;
  \item continuous and peak driver ratings, logic thresholds, flyback
    strategy, and thermal behavior;
  \item separate logic and motor-power paths plus grounding or isolation;
  \item a physical switch that removes motor power;
  \item a restrained motor or raised wheel with no pinch or entanglement path;
  \item measured inactive, forward, reverse, dead-time, reset, and fault states.
\end{itemize}

\lessonbox{\textbf{Stop rule.} Software shutdown is not an emergency stop.
Remove motor-supply power with the physical switch. USB may remain connected
only if the selected module cannot back-power the Mega. Uncertainty stops the
E2 continuation; it does not block the LED simulation.}

\section{Exercises}

\begin{enumerate}
  \item Draw the three evidence signals for a forward-to-reverse request.
  \item Explain why the snapshot needs both requested and applied commands.
  \item Add a same-direction duty change to the deterministic host trace.
  \item Inject stop one tick before the reversal deadline and predict every
    later snapshot.
  \item Design a separate wheel-encoder observation interface. State why
    commanded direction is not observed direction.
\end{enumerate}
