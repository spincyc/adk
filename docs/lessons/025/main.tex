\section{Mission}

Preserve the evidence chain:
\[
\text{capture}\rightarrow\text{frame}\rightarrow\text{validity}
\rightarrow\text{canonical record}\rightarrow\text{visible cadence}.
\]
The Mega exercise captures an identified active-low receiver while an owned
ordinary kit remote supplies known harmless NEC buttons. Deterministic host
tests supply valid, unknown, timing, integrity, repeat, overflow, and record
fixtures. Nothing emits infrared, exports raw pulses, maps a command to an
action, or replays captured evidence.

\lessonbox{\textbf{Evidence before meaning.} A numeric address or command is a
decoded field, not an instruction such as ``unlock'', ``open'', or ``launch''.
Unknown or invalid evidence remains unknown or invalid.}

\subsection{Learning outcomes}

\begin{itemize}
  \item distinguish capture, frame, validity, and record;
  \item explain why invalid evidence is not an exceptional API failure;
  \item validate leader timing, bit timing, and inverse fields independently;
  \item encode a stable record into caller-owned bounded storage;
  \item observe decode classes without relying on Serial;
  \item explain pin, interrupt, snapshot, and acknowledgement ownership.
\end{itemize}

\section{Bounded evidence model}

\texttt{PulseCapture} owns D2 and its external-interrupt resource through
\texttt{MegaPulseCaptureIo}. Receiver \texttt{LOW} maps to \texttt{Mark};
\texttt{HIGH} maps to \texttt{Space}. The ISR stores bounded edge timestamps
only. A published \texttt{PulseFrame} borrows immutable storage and carries its
count, sequence, and capture state.

\begin{tabularx}{\linewidth}{@{}l X@{}}
\toprule
Type or operation & Contract\\
\midrule
\texttt{Pulse} & one \texttt{Mark} or \texttt{Space} and bounded duration\\
\texttt{PulseCapture} & own pin/interrupt and publish stable bounded evidence\\
\texttt{PulseFrame} & immutable pulse span, sequence, and capture state\\
\texttt{InfraredDecoder::decode()} & validate evidence into an \texttt{InfraredFrame}\\
\texttt{InfraredFrame} & protocol, validity, numeric fields, and sequence\\
\texttt{InfraredRecordEncoder::encode()} & write one exact record into caller storage\\
\bottomrule
\end{tabularx}

The decoder recognizes the ordinary 8-bit-address NEC form used by the known
fixture. It checks a leader, exactly 32 bits, a final mark, and both inverse
bytes. Timing windows are inclusive. Noise before or after an otherwise valid
sequence cannot be accepted as an embedded frame.

The first capture configuration accepts 100--10,000 \(\mu\)s pulse durations
and requires a 12,000 \(\mu\)s frame gap. These are software gates, not optical
range or receiver-performance claims. A frame stays stable until
\texttt{acknowledge(sequence)} succeeds. An overrun cannot mutate it.

\subsection{Status is not validity}

An invalid pointer is an API error: \texttt{decode()} returns a non-OK
\texttt{Status} and leaves the destination unchanged. A well-formed
\texttt{PulseFrame} containing unknown, truncated, overflowed, or
integrity-invalid evidence is different: decoding succeeds and the
\texttt{validity} field carries that observation.

Invalid evidence keeps address and command zero. Code must branch on
\texttt{validity} before using either numeric field.

\subsection{Canonical record}

\begin{verbatim}
IR1,<sequence>,<protocol>,<validity>,<address-hex>,<command-hex>\n
\end{verbatim}

Decimal sequence spelling, uppercase names, eight uppercase hexadecimal
digits, commas, and final newline are fixed. The encoder returns
\texttt{Result<uint16\_t>}; check \texttt{ok()} before reading
\texttt{value()}. A short destination receives no partial record.

\section{Narrative example}

\begin{lstlisting}[style=adkcpp]
if (!observeInfrared (adk::MicrosecondTimePoint (micros ())))
{
    stopSafely ();
    return;
}

if (!showFrameEvidence (adk::TimePoint (millis ())))
{
    stopSafely ();
}
\end{lstlisting}

Objects appear in dependency order: runtime, capture adapter, owned capture,
owned LEDs, pure decoder, then pure encoder. Setup acquires D2, its interrupt,
and both evidence outputs before illuminating D13. The loop updates capture,
decodes a stable frame, records it, acknowledges its sequence, and shows D45.

Host tests replay these deterministic fixture classes:

\begin{tabularx}{\linewidth}{@{}l X l@{}}
\toprule
Fixture & Deliberate evidence & D45 result\\
\midrule
Known NEC & valid leader, 32 bits, inverse fields, final mark & one 1 s pulse\\
Unknown & leader outside the accepted interval & two 150 ms pulses\\
Fault & timing, integrity, overflow, or record failure & four 100 ms pulses\\
\bottomrule
\end{tabularx}

Record output is optional supporting evidence. The LED cadence and TP-LED
waveform are the primary observation path.

\section{Predict, observe, interpret}

\subsection{Experiment A: acquisition}

\textbf{Predict.} D13 illuminates only after D2, its interrupt, and both LED
endpoints initialize.

\textbf{Observe:} \blank{55mm}.

\textbf{Interpret.} This supports acquisition. It does not establish capture
timing, D45 cadence, or safe shutdown.

\subsection{Experiment B: class cadence}

Before uploading, identify the receiver from its marking and primary
datasheet. Predict TP-IR idle high and an active-low frame from one known
button. Attach both probe channels while unpowered.

Agreement supports the path from light through capture and decode to visible

\subsection{Experiment C: stable record}

Optionally run the CLI serial logger. Predict a record only after the owned
remote's harmless numeric fixture fields have been reviewed. Observed bytes:
\blank{95mm}. Compare exact case, field order, widths, and newline. A log never
substitutes for TP-IR and TP-LED.

\subsection{Experiment D: safe state}

Invoke the stop path. Predict both LEDs inactive and D45 released. Observe the
LED, then measure the pin separately with the appropriate high-impedance
instrument. A dark LED alone does not prove high impedance or claim release.

Recorded safe-state evidence: \blank{80mm}.

\section{Diagnosis}

\begin{tabularx}{\linewidth}{@{}l X@{}}
\toprule
Observation & Check next\\
\midrule
D13 dark & D2 interrupt or LED claim conflict, initialization status, board power\\
D13 on; D45 dark & TP-IR activity, D45 polarity, resistor, LED orientation\\
No complete frame & receiver identity, idle gap, pulse limits, interrupt ownership\\
Valid becomes unknown & leader levels, durations, exact pulse count\\
Valid becomes fault & mark/space timing and inverse bytes\\
Serial record absent & encoder result and caller buffer; use D45 as primary evidence\\
D45 remains driven after stop & safe-state failure; remove USB and record deviation\\
\bottomrule
\end{tabularx}

\section{Owned receive-only boundary}

\texttt{PulseCapture} and \texttt{MegaPulseCaptureIo} own the D2 pin and
interrupt. For the identified active-low demodulating receiver, \texttt{LOW}
maps to \texttt{Mark} and \texttt{HIGH} maps to \texttt{Space}. The ISR records
bounded timestamps only; decoding, records, and policy remain outside the ISR.

Before powering a module, record its exact marking and primary datasheet.
Verify supply range, pinout, idle polarity, carrier band, output levels, and
Mega compatibility. A three-pin module that resembles another receiver does
not inherit its ratings.

Capture acceptance remains incomplete until host tests prove:

\begin{itemize}
  \item pin and interrupt ownership with reverse-order rollback;
  \item frame-gap, minimum-pulse, and maximum-pulse validation;
  \item stable completed snapshots until matching acknowledgement;
  \item explicit overflow, timing-fault, overrun, and stale-acknowledgement results;
  \item shutdown during capture, interrupt disable, and resource reuse;
  \item timestamp-wrap behavior and deterministic replay.
\end{itemize}

Use only an owned ordinary kit remote and named harmless buttons. Do not export
or replay unknown captures. No transmitter, jammer, brute-force mapping,
credential action, or safety-critical command belongs in this lesson.

\section{Exercises and primary reading}

\begin{enumerate}
  \item Change one inverse byte while preserving valid timings. Predict the
        validity and cadence before running a host test.
  \item Prove that a one-byte-short record buffer remains unchanged.
  \item Explain why \texttt{UnknownProtocol} belongs in frame validity while a
        null pulse pointer belongs in \texttt{Status}.
  \item Design a receiver overrun experiment that never transmits or exports
        the captured waveform.
  \item Sketch how a matching sequence acknowledgement prevents a stale caller
        from clearing newer evidence.
\end{enumerate}
